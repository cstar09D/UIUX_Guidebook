# 필수 UI 8개 확장 검수 기록

Select는 후속 요청으로 목록과 같은 커스텀 패널로 변경했습니다. 최신 구현·확인 결과는 [Select 외형 통일 검수](select-review.md)를 참고하세요. 아래의 native select 기록은 변경 이전의 검수 이력입니다.

확인일: 2026-11-26. [출시 50개 계획](planning/release-50.md)의 1단계이며, 기존 6개와 신규 8개로 현재 14개를 구현했습니다. 남은 36개는 예정 항목입니다. UI별 동작·예외·공식 문서는 [이번 명세](planning/essentials-spec.md)에 연결했습니다.

## 자동 검사

`npm run build`와 자동 테스트 23개가 통과했습니다. Next 빌드의 TypeScript 검사, 14개 UI별 HTML·JS 구문 및 CSS 파싱, React 부분 코드와 전체 코드 28개 타입 검사, 게시 가능 콘텐츠·45개 화면 예시·직무별 안내, 출시 50개 id·제작 묶음 수, 검색·반복 재생·저장·분류·백업·충돌 검증을 포함합니다.

데이터 테스트는 임시 SQLite에서 수행했습니다. 기존 사용자 id가 신규 기본 항목과 같아도 덮어쓰지 않고, 초안·게시본·휴지통을 보존하며 이전이 한 번만 실행되는 것을 검사했습니다.

## 브라우저 동작

Aside 브라우저에서 개발용 DB를 분리한 프로덕션 빌드로 확인했습니다.

| UI | React·HTML에서 확인한 동작 |
|---|---|
| Tooltip | 포인터 호버, 설명 영역으로 이동해 유지, 키보드 진입·Esc로 설명만 닫기, 터치용 도움말 펼침 |
| Popover | 비모달 설정 열기, 임시값 선택·Esc/닫기 취소, 재진입 시 현재 적용값 복원, 적용 후 목록 간격 변경·실행 버튼 복귀 |
| Toast | 성공 표시, 호버 5.5초 동안 유지, 이탈 후 자동 닫힘, 최근 알림 기록, 지속 실패 안내·Enter로 재시도 |
| Tabs | 방향키·Home/End 이동, 자동 전환, 수동형 초점/선택 분리, Enter 또는 Space 활성화 |
| Select | 미선택 적용 오류, 값 선택·적용·오류 해제, 네이티브 목록 사용 |
| Switch | 켜짐·저장 중·성공, 실패 모의·이전값 복원, 저장 중 재조작 차단 |
| Checkbox | 개별 선택·전체 선택·선택 개수, 부분 상태에서 모두 선택 |
| Radio Group | 미선택 확인 오류, 하나만 선택, 화살표로 선택 변경, 확인 결과 |

모의 저장과 화면 비활성 처리가 결합되어 스위치가 대기 상태에 머무는 문제를 수정했습니다. 실제 저장에 해당하는 모의 요청은 화면 표시 여부와 분리하고 iframe 진입 시 visibility를 동기화했습니다. 재시도 성공 시 사라지는 오류 버튼에 초점이 남지 않도록 원래 실행 버튼으로 복귀시켰습니다.

## 크기·고정 헤더·코드

- 새 8개를 각각 390×844와 320×640에서 확인했습니다. 직접 체험의 body `scrollWidth=clientWidth`, 관찰 장면 너비와 컨테이너 너비 일치, 문서 가로 넘침 0입니다. [측정값](qa/essentials/mobile-metrics.json)에 16개 조합을 기록했습니다.
- 390px에서 상세 높이 700px, 320×640에서 640px로 제한됩니다. 사용 가이드·관찰·코드 전환에서 높이를 유지했습니다.
- Popover를 모바일 폭에서 열었을 때 패널 범위 x=12~302, y=12~293.7로 iframe 333×390 안에 들어왔습니다. [화면](qa/essentials/popover-mobile.png).
- 상세 본문을 scrollTop=3210까지 내려도 헤더 상단 72px·닫기 버튼 95px 위치가 유지됐습니다. 코드 화면 너비 320px와 scrollWidth 320px가 일치했습니다. [코드 화면](qa/essentials/code-mobile.png).
- 목록의 스위치·체크박스 미리보기 위아래 잘림을 발견해 작은 장면만 압축했습니다. 수정 후 새 8개 카드 모두 컨테이너 밖 세로 넘침 0을 확인했습니다. [수정 화면](qa/essentials/selection-cards.png).
- UI 부분 코드가 기본 선택이며 복사 완료 상태를 확인했습니다. 전체 예제는 선택 후에만 표시되고 `radio-group.html` 다운로드에 독립 HTML 문서와 해당 native radio 코드가 포함됐습니다.

브라우저 자동화의 iframe 내 재시도 버튼 클릭이 한 번 바깥 영역에 전달돼 상세가 닫혔습니다. 같은 작업을 키보드 Enter로 재확인해 두 구현의 복구 동작을 확인했습니다. 최초 포커스만 설정하는 자동화 동작과 실제 키보드 진입도 구분해 확인했습니다.

## 실제 데이터 반영

사용자 로컬 DB에는 새 8개만 추가했습니다. API 응답 200·게시 목록 14개를 확인했고, 확장 전의 6개 term 원문·게시본·메타 정보와 변경 이력 9건을 SQL 원문 비교로 모두 보존했습니다. `data/backups/catalog-*.json`에 확장 전 6개 콘텐츠·이력을 포함한 복구 파일을 생성했습니다. 새 카테고리는 기존 분류 뒤에 필요한 항목만 추가했습니다.

관리 목록과 등록된 시뮬레이션은 새 항목을 기존 편집·초안·게시·숨김·순서·백업 흐름에 연결합니다. 사용자 콘텐츠를 검증 목적으로 수정하거나 초기화하지 않았습니다.

## 남은 검증

브라우저 폭 전환은 실제 iOS·Android 선택 창, 가상 키보드, 화면 읽기 프로그램 검증을 대체하지 않습니다. VoiceOver·TalkBack의 낭독과 실제 터치·회전·키보드는 후속 실기기 검수 대상입니다. 2~4단계 36개는 별도 제작·검수해야 합니다.

## 후속 조정: 상세 모달 높이

같은 날 사용자 요청으로 기본 높이를 700px에서 900px로 변경했습니다. PC에서는 화면 위아래 16px씩 남기는 높이를 상한으로 사용하고 모바일에서는 화면 높이로 제한합니다. 제목·닫기 고정과 본문 스크롤 구조는 유지합니다.

바텀시트 상세의 왼쪽 체험 영역은 652px입니다. 1440×1000에서는 모달 900px·본문 752.3px, 1280×900에서는 868px·720.3px, 1280×844에서는 812px·664.3px로 왼쪽 전체가 스크롤 없이 보이는 것을 측정했습니다. 390×844에서는 모달 844px로 왼쪽 전체가 보입니다. 320×640처럼 높이가 부족한 화면은 화면 높이로 제한하고 본문 스크롤로 접근합니다. 빌드·TypeScript 검사와 API 정상 응답을 확인했습니다. 스크린샷 캡처는 브라우저 CDP 시간 초과로 실패했으며 위 결과는 DOM 크기 측정에 근거합니다.
