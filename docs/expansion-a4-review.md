# A4 배치·스크롤 UI 6개 · 기존 4개 보강

검수일: 2026-11-28. Turso 관리자 콘텐츠와 실행 데모는 **101개**, 공개 목록은 **77개**다. 확장 A1~A4 신규 24개는 초안이다. 로컬 개발 첫 화면은 로그인 없이 전체 초안을 검토하며 관리자 편집 기능은 로그인을 유지한다. 이번 작업에서 게시·GitHub push·Vercel 배포는 실행하지 않았다.

| UI | 직접 체험 |
| --- | --- |
| Split View / Resizable Panels | 편집과 결과 비교, 포인터를 따라오는 분할선, 25~75% 경계, 방향키·Home/End·비율 버튼, 작은 화면 편집/결과 탭과 입력 보존 |

목록 루프와 상세 체험은 같은 Scene·컨트롤러·예제 데이터를 사용한다. 짧은 목록에서는 보조 옵션·긴 문구를 줄인다. 신규 6개 원고에는 실무 추천, 상태별 발생 조건과 처리, 대안 UI 바로가기, 네 직무별 결정·전달·검토 내용을 작성했다. 부분 코드와 전체 실행 예제는 HTML/CSS/JavaScript 및 React/TypeScript 두 형식으로 생성한다.

실제 상태 계약은 확장 **24개**에 적용된다. 기존 77개 상태 선택은 설명용 화면이며 이번 보강 변형은 직접 체험 내부 옵션에서 선택한다.

## 기존 UI 보강

- **Navigation Drawer**: 모달 탐색 외 고정 사이드바·아이콘 축약·보조 패널을 제공한다. 고정/축약/보조는 비모달이고 작은 화면에서는 모달 탐색으로 전환한다. 선택한 문서는 유지한다.
- **Progress Bar**: 같은 진행값을 선형·원형·나란히 비교한다. 원형 SVG는 pathLength 100과 dashoffset 100-진행값을 사용한다. 완료·취소·60% 실패는 기존 요청 상태를 공유한다.
- **Sticky Header**: 기존 고정/해제를 유지하고 아래 방향에서는 숨김, 위 방향·상단·헤더 안 초점에서는 복귀하는 변형을 추가했다. 전체 페이지가 아닌 내부 문서만 관찰한다.
- **Particles**: 기존 지속 부유를 유지하고 한 번만 축하하는 Confetti를 추가했다. 최대 24조각·1.2초 수명·중복 트리거 방지·화면 밖/숨긴 탭 정리·모션 감소 대안을 제공한다. 조각이 사라져도 성공 문구는 남는다. 실제 데이터 저장은 모의하지 않는다.

## 검수와 보정

- 프로덕션 빌드와 생성된 **101개** 독립 예제·부분 코드의 타입 검사를 통과했다.
- 회귀 테스트 **86개 통과**. 분할 비율 경계와 신규 초안 추가·기존 가이드 추가 시 사용자 원고/게시본/이력 보존 및 재실행 중복 방지를 추가 검증했다.
- 분할선 Home/End에서 25/75%를 확인했다. 포인터 이동 중 비율이 변경되고, 모바일 결과 탭에도 작성한 `분할 테스트🙂`가 유지됐다.
- 메가 메뉴의 링크 선택·현재 문서·Esc 닫기와 호출 버튼 초점 복귀를 확인했다. 링크의 보조 문구가 현재 문서 제목에 섞이던 오류를 고쳐 제목과 aria-current는 목적지 이름만 사용한다.
- 스크롤 리빌은 처음부터 영역 안의 카드가 나타나고 내부 End 이동에서 마지막 카드가 나타났다. 반복 모드에서도 영역 진입 4/4개를 확인했다.
- 순차 등장 160ms 간격은 총 840ms로 안내하고 완료 후 네 항목의 opacity가 모두 1이었다. 순서 뒤집기는 DOM ID도 3/2/1/0으로 바꾼다.
- 스크롤 스냅은 End 후 4/4, 다음 비활성·이전 활성 상태였다. 패럴랙스는 끝에서 배경 48px·전경 -30px, 정적 전환 후 양쪽 0px를 확인했다.
- Drawer는 PC 축약에서 문서를 선택한 뒤 모바일 모달로 바꿔도 같은 문서가 선택되어 있었다. 진행률은 React 실패 시 선형/원형 60과 arc 40, HTML 완료 시 양쪽 100과 arc 0을 확인했다.
- 방향 헤더는 아래로 이동하면 숨김 클래스를 적용하고 헤더의 목차 링크에 초점이 들어오면 복귀했다. Confetti는 24개로 제한되고 수명 후 조각 0개·완료 문구 유지였다.
- 390px에서 신규 6개 HTML 조작, 320px에서 React의 모바일/등장/정적/마지막 카드/시차 상태를 확인했다. 바깥 문서는 320/320px였으며 iframe 본문도 각 화면에서 clientWidth와 scrollWidth가 일치했다. 내부 Scroll Snap의 가로 이동은 의도된 동작이다.
- 목록의 메가 메뉴 열림 단계 잘림을 발견해 보조 설명·여백을 조정했다. 상세에는 같은 설명을 계속 제공한다.

이번 검수는 데스크톱 브라우저의 마우스·키보드·화면 폭 범위다. 실제 iOS/Android 관성 스크롤과 보조 기술은 별도 검수가 필요하다. 기존 Halftone clip-path 소수점 정규화 hydration 경고는 후속 점검 항목으로 남아 있다.

분할선의 의미·값·키보드 처리는 [W3C APG Window Splitter](https://www.w3.org/WAI/ARIA/apg/patterns/windowsplitter/)를 다시 확인했다. 이 문서도 예제 검토가 진행 중임을 명시하므로 동일 구현만으로 보조 기술 호환 검수를 완료했다고 간주하지 않는다.

## 데이터 반영

로컬 SQLite는 수정하지 않았다. Turso에서 작업 전 복구 지점을 생성한 뒤 추가 전용 스크립트를 적용했다. 기존 95개의 게시본이 모두 동일하며 바뀐 기존 초안은 navigation-drawer·progress-bar·sticky-header·particles 네 개뿐이다. 신규 6개는 draft이고 두 스크립트의 재실행 변경 대상은 0개다.

```sh
# 기본은 미리보기, --apply를 붙인 경우만 서버 초안 반영
node --env-file=.env.deploy.local scripts/add-expansion-drafts.mjs
node --env-file=.env.deploy.local scripts/refresh-layout-guides.mjs
```

로컬 확인: `/?term=split-view`. 1차 계획의 신규 24개 묶음은 A4까지 구현했다. 다음은 1차 전체 통합 검수·검토 후 코드 배포와 초안 게시 순서를 정하는 단계이며, 스타일·디자인 기초는 별도 후속 기획으로 유지한다.
