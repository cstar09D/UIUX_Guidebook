# 1차 확장 통합 검수

검수일: 2026-11-28. A1~A4의 신규 24개를 대상으로 목록 진입·상세·상태 선택·코드 형식·관리자 미리보기를 함께 점검했다. 로컬 개발 첫 화면은 비로그인 101개, 운영 빌드는 게시본 77개다. 이번 검수에서는 Turso 콘텐츠 저장·게시·GitHub push·Vercel 배포를 실행하지 않았다.

## 수정한 문제

| 문제 | 수정과 확인 |
| --- | --- |
| 초기 렌더링 불일치 | 미리보기 iframe의 무작위 nonce를 서버 렌더링 중 생성하지 않고 브라우저가 준비된 뒤 생성한다. 준비 전에는 동일한 안내 마크업을 사용한다. 두 형식의 서버 마크업을 반복 비교하는 회귀 검증을 추가했다. 새 프레임은 스스로 기본값을 초기화하고 부모는 선택한 프리셋이 있을 때만 복원한다. |
| 하프톤 CSS 정밀도 | 하프톤과 전후 비교의 clip-path를 브라우저가 정규화하는 단위·정밀도로 출력해 서버/클라이언트 스타일 차이를 없앴다. 경고를 숨기는 속성은 추가하지 않았다. |
| 분할 화면 상태 설명 | 45% 같은 임의 비율을 50:50으로 안내하지 않고 직접 조작 상태로 유지한다. 모바일 전환은 compact 상태로 반영하고, 숨는 분할선에 초점이 있었다면 표시되는 탭으로 돌린다. |
| Scroll Reveal 프리셋 | ‘진입 전’을 선택하면 대기 중 관찰 응답이 카드를 다시 표시하지 못하게 한다. 스크롤·초점 접근 후 실제 관찰로 이어지고 모두 표시된 상태를 마지막 스크롤 이벤트가 ‘등장 중’으로 되돌리지 않는다. 정적·반복 모드의 상태도 구분한다. |
| HTML 헤더 초점 복귀 | onfocusin 속성 대입을 실제 focusin 리스너로 바꿔 숨김 클래스를 제거한다. CSS 초점 표시와 실제 상태를 일치시킨다. |
| 관리자 상태 편집 | 선택한 예시가 편집 중 제거되면 현재 유효한 예시 키를 기준으로 기본 체험을 다시 동기화한다. 안내 문구를 실행 코드로 평가하지 않는 기존 계약을 유지한다. |

## 통합 경로 검수

[48개 형식 조합 기록](qa/expansion-integration/matrix.json)은 신규 24개 각각을 목록 카드에서 열고 대표 상태를 고른 뒤 React → HTML로 전환한 결과다. 매 조합에서 올바른 demo ID의 실행 루트, 콘텐츠, 부분 코드 기본 선택과 코드 영역 폭을 확인했다. **루트 불일치 0건·코드 가로 넘침 0건**, 전체 48개가 부분 코드를 기본으로 표시했다. 각 UI의 모든 입력·실패·복구 조합을 이번 매트릭스 한 번으로 전부 검증했다는 뜻은 아니며, 세부 기능은 A1~A4 검수 기록을 함께 따른다.

[추가 조작 기록](qa/expansion-integration/checks.json):

- Badge의 137개/99+ 상태는 HTML로 바꿔도 유지되고 초기화 후 기본 3개·기본 체험으로 돌아왔다.
- Scroll Reveal의 진입 전은 네 카드 모두 shown=false·opacity=0이었다. 내부 End 이동 후 네 카드가 표시되고 상태도 visible이 됐다.
- 분할선의 ArrowLeft는 45%를 표시하면서 50:50 설명을 남기지 않았다. 모바일에서는 compact 상태와 편집 탭의 초점을 확인했다.
- 관리자 Badge 편집의 시뮬레이션 탭에서 99+ 상태·HTML 전환·목록 애니메이션 연결을 확인했다. 저장이나 게시 없이 닫았다.
- HTML 방향 헤더의 목차 링크에 초점이 들어오면 숨김 클래스가 제거됐다.
- 전체 HTML은 ‘전체 실행 예제’를 선택한 뒤에만 표시됐다. 390px의 전체 코드 영역은 clientWidth/scrollWidth가 320/320px였다.
- ‘시차 스크롤’ 검색은 Parallax 한 개를 찾았다. 입력과 검색·레이어와 도움말을 함께 선택하면 두 분류의 항목만 표시됐다.

실제 iOS/Android 터치·키보드와 보조 기술 검수는 별도다. 이번 통합 검수는 데스크톱 브라우저의 목록/모달·키보드·화면 폭·관리자 연결 범위다.

## 빌드·데이터·운영 경계

- `npm run build` 통과: 101개 독립 예제와 부분 코드 타입 검사 포함.
- `npm test` **88개 통과**: 서버 초기 마크업 안정성과 관찰 응답·스크롤 완료 상태 회귀 검증 포함.
- 별도 3001 포트의 운영 빌드도 확인했다. [환경별 결과](qa/expansion-integration/environments.json): 개발 첫 화면 101개, 운영 첫 화면 77개. 쿠키 없는 운영 관리자 API는 401, 관리자 페이지는 로그인으로 307 이동한다. 검수 후 임시 운영 서버는 종료한다.
- [Turso 보존 결과](qa/expansion-integration/db-verification.json): 공개 77개·관리자 101개, 기존 게시본 동일, 추가·가이드 보강 재실행 대상 0개. 이 기록의 기존 초안 4개 변경은 A4에서 추가했던 안내를 작업 전 체크포인트와 비교한 결과다. 본 통합 검수에서 추가로 저장한 콘텐츠는 없다.

단계별 기록: [A1](expansion-a1-review.md), [A2](expansion-a2-review.md), [A3](expansion-a3-review.md), [A4](expansion-a4-review.md).

현재 실행 상태 계약은 신규 24개 대상이다. 기존 77개 상태 선택은 설명용 화면을 유지하며 관련 변형은 직접 체험 내부에서 비교한다. 다음은 검수한 소스의 GitHub 반영·Vercel 배포와 초안 24개의 게시 순서를 진행하는 단계다. 새 demo ID를 실행할 소스가 준비되기 전에 서버 초안을 먼저 게시하지 않는다.
