# 2단계 실행·입력·탐색 UI 검수 기록

확인일: 2026-11-26. [출시 50개 계획](planning/release-50.md)의 2단계 12개를 추가해 총 26개를 구현했습니다. 남은 24개는 3·4단계입니다. 공식 문서와 시연·체험의 범위는 [2단계 명세](planning/foundations-spec.md)에 정리했습니다.

## 자동 검사

프로덕션 빌드와 자동 테스트 24개가 통과했습니다. 26개 등록 연결, 게시 가능한 원고, 81개 상황별 화면 예시와 직무별 안내, 코드 분리·HTML/JS/CSS 구문, 독립 React 부분·전체 코드 52개 타입 검사, 검색·반복 재생·로컬 요청 제한·저장·백업·충돌·추가 이전을 포함합니다. 저장소 테스트는 임시 DB를 사용했습니다.

2단계 이전 검사는 기존 14개 초안·게시본·휴지통·이력을 원문으로 비교하고 새 12개만 한 번 추가되는 것을 확인합니다. 기존 id가 있으면 덮어쓰지 않습니다.

## 실제 조작

Aside 브라우저와 별도 검증 DB를 사용하는 프로덕션 서버에서 React·HTML 두 형식을 모두 확인했습니다.

| UI | 확인한 동작 |
|---|---|
| Button | 저장 중 중복 실행 차단, 완료 횟수, 실패 모의·다시 실행 |
| Icon Button | 이름 있는 아이콘, 키보드 실행, 복사·공유 모의 안내, 보관·취소·버튼 초점 복귀 |
| Toggle Button | Enter/Space 전환, 굵게·기울임 독립 선택, aria-pressed와 샘플 서식 일치 |
| Segmented Control | 월간·연간 단일 선택, 방향키 이동, 가격·기간 동기화 |
| Text Field | 빈 값·최소·최대 길이 오류, 31자 원문 보존, 오류 시 입력 초점, 정상 Enter 저장 |
| Textarea | Enter 줄바꿈, 짧은 값·201자 오류와 원문 보존, 글자 수·정상 저장 |
| Search Field | 검색 결과 1건, 0건과 실패 구분, 검색어 보존, 초기화 |
| Slider | 방향키·Home/End, 0·100 경계, 잘못된 53 입력 시 기존값 보존, 75 적용 |
| Breadcrumb | 상위·루트 이동, 경로·제목·현재 위치 동기화, 목적지 제목 초점, 복원 |
| Pagination | 1·2·3 페이지 결과, 이전·다음, 첫·끝 경계, 현재 페이지, 결과 제목 초점 |
| Disclosure | Enter 펼침, Space 접기, native details의 open 상태 |
| Inline Alert | 정보·완료·주의·실패, 재시도 중 차단, 재실패·성공, 사라지는 재시도 버튼의 초점 복구 |

폼 체험의 제출이 iframe 정책에 막힌 것을 발견해 sandbox에 `allow-forms`를 추가하고 세 입력 폼의 제출을 다시 확인했습니다. 예제는 제출의 기본 탐색을 막고 로컬 상태만 갱신합니다. 같은 출처 접근 권한은 추가하지 않았습니다.

인라인 알림의 재시도 성공 후 비활성 버튼에 초점을 주던 시점을 렌더 완료 뒤로 옮겼습니다. 수정 후 완료 선택 버튼으로 복귀하는 것을 확인했습니다. 텍스트에어리어와 페이지네이션의 작은 목록 시연에서 넘치는 보조 문구를 정리했고, 새 12개 모두 카드 캔버스 위아래 넘침이 없었습니다.

## 화면·코드

- PC 1440×1000, 모바일 폭 390×844·320×640에서 확인했습니다. 기본 모달 높이 900px과 화면 높이 상한, 고정 제목·닫기를 유지합니다.
- 390px에서 12개 모두 React·HTML 체험과 코드의 `scrollWidth=clientWidth`, 모바일 관찰 장면과 내부 프레임 너비 일치, 문서 가로 넘침 0입니다. [측정값](qa/foundations/responsive-390.json).
- 320px에서 12개 React 체험과 모바일 관찰의 가로 넘침이 없고 모달은 640px로 제한됩니다. 관찰 너비는 패딩을 제외한 내부 프레임을 기준으로 비교했습니다. [측정값](qa/foundations/responsive-320.json).
- PC 텍스트 필드의 오류·초점·상세 설명 배치를 [화면](qa/foundations/text-field-desktop.png)으로 확인했습니다.
- 실제 사이트의 390px [검색 입력 화면](qa/foundations/search-field-mobile.png)에서 검색창·행동·상태 문구와 고정 헤더가 잘림 없이 표시되는 것을 시각적으로 확인했습니다.
- UI 부분 코드가 기본이며 복사 완료 응답을 확인했습니다. 전체 실행 예제 선택 후 내려받은 `text-field.html`에는 독립 문서와 해당 필드의 HTML·CSS·실행 함수가 들어 있었습니다. OS 클립보드 내용을 직접 읽어 대조한 결과는 아닙니다.
- 페이지네이션 관찰에서 자동으로 1 → 2 → 3 → 1 → 2가 표시되어 주기 반복을 확인했습니다. 전체 시연의 반복 시간·등록 연결은 자동 검사에도 포함합니다.

## 실제 데이터 반영

사용자 DB에 새 12개를 추가하고 API 200·게시 목록 26개를 확인했습니다. 이전 전 기존 14개의 term·게시본·메타 정보, 이력 17건과 기존 설정은 SQL 원문 비교로 모두 보존했습니다. 추가한 항목은 각 revision 1, catalog 이력 1건과 게시본을 가집니다.

확장 전 14개·이력 17건을 담은 `data/backups/catalog-*.json` 복구 지점을 자동 생성했습니다. [비교 결과](qa/foundations/migration-result.json). 실제 콘텐츠를 검증 목적으로 수정하거나 초기화하지 않았습니다.

실제 브라우저에서 관리 목록 26개·게시 노출 26개, 시뮬레이션 등록 26개와 각 연결 콘텐츠 1개, 새 자동 복구 지점 표시를 확인했습니다. 공개 목록의 `밀어서 조절` 검색은 Slider 한 개를 반환하고 지우기 후 26개로 복원됐습니다.

## 후속 검증

폭 변경은 실제 iOS·Android 실기기 검증을 대체하지 않습니다. 한글 IME의 실제 조합 과정, OS 키보드·터치·VoiceOver/TalkBack과 여러 브라우저 검수는 남아 있습니다. 복사·공유·저장·검색은 예제의 로컬 모의 동작이고, 실제 서버·라우터·OS 공유 연동은 각 가이드에 통합 시 확인할 사항으로 명시했습니다. 3·4단계 24개는 후속 제작 범위입니다.
