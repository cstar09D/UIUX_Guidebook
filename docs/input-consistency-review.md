# 입력값·검색 결과 일치 검토

확인일: 2026-11-26. 콤보박스의 ‘서울’ 입력 오류를 계기로 입력값·추천·선택·적용값을 나누어 사용하는 부분을 검토했습니다.

## 발견과 수정

| 영역 | 원인·증상 | 수정 |
|---|---|---|
| React 콤보박스 | 표시 글자와 필터 검색어를 따로 저장하고 조합 중 검색어 갱신을 건너뜀. ‘서’에서 ‘서울’ 조합 중 이전 3개 후보가 남음 | 표시 글자를 유일한 필터 기준으로 사용. 조합 중에도 즉시 후보 갱신 |
| HTML 콤보박스 | compositionstart~end 사이 input에서 목록 갱신을 건너뜀 | 매 input에서 필터링. 조합 상태는 키보드 선택 방지에만 사용 |
| 사이트 상단 검색 | 입력 초안과 검색 조건 분리로 같은 지연 발생 | 입력창·결과·결과 제목을 하나의 검색어 상태로 갱신 |
| 콤보박스 키보드 | 조합 종료 직전 isComposing=false인 Enter 처리, 닫힌 목록의 ArrowDown에서 두 번째 후보 시작 | 조합 ref·isComposing·keyCode 229를 함께 확인. 닫힌 목록은 아래 방향키 첫 후보·위 방향키 마지막 후보로 시작 |
| 콤보박스 안내·닫기 | HTML의 이전 ‘선택 완료’가 새 입력 후에도 남음. Tab으로 떠나도 목록이 남을 수 있음 | 입력 시 선택 안내 초기화. 입력 영역 밖으로 초점이 나가면 목록 닫기 |
| 모달 설정 | React에서 저장한 이름과 편집 중인 이름을 공유해 취소해도 바깥 제목이 바뀜. HTML은 다시 열 때 취소한 초안이 남음 | 저장값과 편집값을 분리하고, 다시 열 때 마지막 저장값으로 복원. 두 구현의 취소 동작 일치 |
| 검색 입력 체험 | 제출형 검색에서 새 글자를 입력하는 동안 이전 결과가 남지만 적용 검색어를 알기 어려움 | 결과와 무결과 안내에 실제 제출한 검색어 표시. 새 입력과 적용된 결과를 구분 |

## 검토 범위

React·HTML 콤보박스, 공개·관리자 검색, 모달, 제출형 검색을 브라우저에서 확인했습니다. 관리자 검색은 입력값을 그대로 사용하고 있어 같은 조합 지연 오류는 없었습니다. 텍스트 필드·여러 줄 입력·슬라이더·체크박스·라디오·세그먼트·토글·셀렉트·스위치·팝오버·그리드의 값 변경, 적용·취소와 안내 연결은 소스로 검토했습니다. 해당 범위에서 추가로 확인된 문제는 위 표에 반영했습니다.

## 검증 결과

- 새 회귀 검사 8개와 기존 검사 24개, 총 32개가 통과했습니다. 새 검사는 실제 컴포넌트 핸들러를 지속되는 hook 상태로 실행하고 HTML 실행 함수를 최소 DOM에서 실행합니다. 수정 전 실패를 확인한 후 수정 뒤 통과를 확인했습니다. 실제 DOM·초점은 아래 브라우저 검사로 별도 확인했습니다.
- React·HTML에서 ‘서’ 3개, ‘서울’ 1개, ‘서귀포’ 1개, 존재하지 않는 도시 0개, 지우기 5개를 확인했습니다. React는 부산 단일 결과도 확인했습니다. 조합 중 추천 일치, 조합 확정 Enter·229 Enter의 선택 방지는 이벤트 순서 회귀 검사에 포함했습니다.
- 닫힌 목록의 방향키·Enter 선택, 새 입력 뒤 선택 안내 초기화, React의 Tab 이탈 닫기를 브라우저에서 확인했습니다. [390px 서울 단일 결과 화면](qa/input-consistency/combobox-seoul-mobile.png)을 시각적으로 확인했습니다.
- 두 모달 체험에서 이름 저장 → 다른 이름 입력 → 취소 → 다시 열기 후 마지막 저장값이 유지됐습니다.
- 두 검색 입력 체험에서 모달 1건 → 입력만 변경하면 ‘모달’ 적용 결과 유지 → 재검색 시 무결과 → 초기화를 확인했습니다. 결과 안내에는 적용 검색어가 표시됐습니다.
- 공개 검색 ‘서치’는 Search Field 한 개, 지우기 후 26개를 반환했습니다. 관리자 ‘텍스트에어리어’는 한 개, 무관한 검색어는 0개를 반환했습니다.
- 프로덕션 빌드와 독립 코드 예제 검사가 통과했습니다. 체험·부분 코드·전체 예제를 같은 원본으로 다시 생성했습니다.
- 로컬 서버를 갱신했습니다. 기존 26개 콘텐츠·게시본·메타 정보·변경 이력 29건·설정은 SQL 원문 비교로 모두 변경 없음을 확인했습니다.

이벤트 회귀 검사는 OS의 실제 한글 조합기를 직접 조작한 검사가 아닙니다. 여러 OS·모바일 키보드·VoiceOver/TalkBack 실기기 검수는 기존 후속 검증 범위로 유지합니다.
