# UI UX 용어 사이트 기획안

작성일: 2026-11-26 · 상태: 구현 전 검토안

후속 확정: [첫 출시 50개 계획](release-50.md)에 선정 범위와 제작 순서를 정리했습니다. 기본 유형 38개에 기간 선택 형태 1개를 더해 현재 39개 구현, 기본 유형 12개 예정입니다. 아래는 최초 조사·기획의 근거 기록입니다.

기획·디자인·퍼블리싱·개발 실무자가 UI의 이름과 동작을 함께 확인하고 실제 업무에 적용하는 참고 사이트를 만든다. 목록에서는 짧은 동작 예시로 UI를 식별하고, 상세에서는 직접 조작하면서 사용 조건·직무별 고려사항·코드를 확인한다. 관리자에서 콘텐츠와 분류를 지속해서 관리한다.

## 확정된 사용자 선택

| 항목 | 선택 |
| --- | --- |
| 주요 이용자 | 기획·디자인·개발 실무자 |
| 첫 출시 범위 | 대표 용어 40~60개를 충실하게 제작 |
| 운영자 | 개발자가 콘텐츠와 시뮬레이션을 모두 관리 |
| 실행 환경 | 우선 사용자 컴퓨터에서 로컬 실행, 공개는 추후 결정 |
| 코드 예제 | HTML·CSS·JavaScript 및 React·TypeScript 모두 제공 |
| 배포 환경 | 미정, 로컬 운영과 향후 이전을 고려해 제안 |
| 관리자 디자인 | 다크 테마 전용 |
| 프론트 디자인 | [우디디자인랩 UI 미니 사전](https://woodydesignlab.com/ui/dict)의 시각 스타일을 기준으로 제작 |
| PC 목록 배치 | 참고 스타일을 유지하면서 넓은 3~4열로 확장 |

이 문서의 기술 구성, 60개 후보, 화면 배치는 위 선택을 바탕으로 한 제안이다. 실제 화면 및 애플리케이션 코드는 이번 기획 단계에 포함하지 않는다.

이 문서의 게시·노출은 로컬 사이트의 열람 화면에 표시하는 의미다. 인터넷 공개·외부 배포와는 별개다.

[60개 후보 목록](catalog.md)에는 영문·한국어 발음·한국어 표현, 사용 상황, 데모 방향, 동작 검색어를 함께 기록했다. 후보마다 동일한 완성 기준을 적용하고 최종 40~60개를 선정한다. 개수를 맞추기 위해 버튼의 색상·크기 변형을 별도 용어로 늘리지 않는다. 아이콘 버튼·토글 버튼 등 별도 설명 가치가 있는 변형에는 상위 용어 관계를 연결한다.

주제와 별도로 콘텐츠 유형을 `컴포넌트 / 패턴 / 레이아웃 / 모션`으로 저장한다. 대표 카테고리는 하나만 두고 보조 태그를 여러 개 연결한다. 스낵바의 슬라이드 모션처럼 서로 다른 축의 속성은 태그와 관련 용어로 연결한다.

## 용어와 출처 편집 기준

화면 표기는 `Modal Dialog / 모달 다이얼로그 / 모달 대화상자`처럼 세 필드를 유지한다. 한국어 발음과 번역은 사이트의 편집 표기이며 보편적인 공식 번역으로 단정하지 않는다. 대표 영문 명칭에는 근거가 되는 표준·디자인 시스템을 표시한다.

관계는 다음처럼 구분한다.

- 동의어·약어: FAB와 Floating Action Button.
- 통칭·검색 유입어: 팝업, 햄버거 메뉴. 의미 범위가 넓으면 설명을 붙인다.
- 하위·변형: 버튼과 토글 버튼, 모달 대화상자와 경고 대화상자.
- 관련·비교: 토스트와 스낵바, 테이블과 데이터 그리드. 완전한 동의어로 합치지 않는다.
- 모션: 슬라이드, 페이드. 여러 컴포넌트가 공유할 수 있다.
- 대안: 호버 도움말의 터치 대안, 무한 스크롤의 페이지네이션 대안. 적용 조건을 함께 적는다.

각 항목은 정의, 사용 상황, 사용하지 말아야 할 상황, 동작 규칙, 직무별 안내, 대안, 출처 URL, 확인일, 원고 검토 상태를 갖는다. 외부 코드·문구를 그대로 대량 복제하지 않고 예시는 자체 작성한다. 외부 코드를 사용하면 해당 라이선스와 고지 조건을 개별 확인한다.

## 이용자 화면

### 목록

상단 소개·검색·추천 검색어 아래에 가로 카테고리 칩과 카드 그리드를 배치한다. [지정된 참고 디자인](https://woodydesignlab.com/ui/dict)에 맞춰 좌측 고정 카테고리 대신 상단 탐색을 사용한다. PC는 넓은 콘텐츠 영역에서 3~4열, 모바일은 2열을 기본으로 한다. 매우 좁은 폭·글자 확대에서는 가독성에 따라 1열로 전환한다. 카테고리는 가로 스크롤을 지원하고 유형·적용 환경은 보조 필터로 제공한다. URL에 검색·필터·정렬 상태를 보존한다. 구체적인 시각 기준은 [디자인 적용안](design-reference.md)을 따른다.

카드 구성 순서는 미리보기, 명칭 세트, 짧은 사용 상황, 별칭·통칭 태그, 적용 환경이다. 제목을 누르면 상세 모달이 열린다. 미리보기 재생 버튼은 별도의 조작 영역으로 둬 상세 열기와 충돌하지 않게 한다. 링크 안에 다른 버튼을 중첩하지 않는다.

동작 예시는 UI를 알아볼 수 있는 2~4초 시나리오로 만든다. 버튼을 누르면 결과가 바뀌는 과정, 아코디언이 펼쳐지는 과정, 스켈레톤이 실제 콘텐츠로 바뀌는 과정을 보여준다. 정적인 컴포넌트에 의미 없는 움직임을 추가하지 않는다.

이미지는 HTML·CSS·SVG로 그린 실제 UI의 대표 상태를 사용한다. 목록 시연과 상세 체험의 이미지 원본을 따로 만들지 않는다. 장면 구성·재생 시계·정지·초기화·코드 연결은 [이미지와 애니메이션 구현 계획](visual-motion-plan.md), 60개 후보별 대표 장면·시연 순서·속성·시간·직접 조작은 [UI별 동작 명세](ui-motion-specs.md)를 따른다. 복잡한 대표 6개는 밀리초 단위 스토리보드를 포함한다.

제안하는 재생 정책은 화면에 들어온 카드만 한 번 재생하고, 재생·정지·다시 보기 및 전체 움직임 끄기를 제공하는 것이다. 동시에 재생하는 카드는 최대 2개로 제한하고 화면 밖은 정지한다. 모션 감소 설정에서는 정적인 시작·끝 상태와 설명으로 대체하고 명시적으로 재생할 수 있게 한다. 이는 [WCAG의 움직임 제어 기준](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)을 참고한 제품 정책이다.

초기 전체 목록은 관리자 지정 순서, 검색 결과는 관련도 순으로 제공한다. 영문·한글 가나다순도 선택할 수 있다. 목록 페이지 자체에는 페이지네이션을 사용해 복귀 위치를 명확하게 유지한다. 무한 스크롤은 용어 데모로 제공한다.

### 검색

검색 대상은 영문, 발음, 한국어 표현, 약어, 통칭, 사용 목적, 동작 설명, 모션 태그다. 관리자가 모든 검색용 문구를 편집할 수 있게 한다.

| 검색 예 | 우선 제시할 결과 |
| --- | --- |
| 모달, modal, 모달 다이얼로그 | 모달 대화상자 |
| 아래에서 올라오는 창 | 바텀시트, 관련 슬라이드 모션 |
| 옆에서 나오는 메뉴 | 내비게이션 드로어 |
| 접었다 펴는 목록 | 아코디언, 디스클로저 |
| 잠깐 나타났다 사라지는 알림 | 토스트, 스낵바 |
| 회색 뼈대, 반짝이는 로딩 | 스켈레톤 |
| 드래그해서 순서 변경 | 드래그 앤 드롭 |
| 팝업 | 여러 레이어 UI와 차이 안내 |

60개 규모에서는 별도 검색 서버나 유료 AI 검색 없이, 정규화한 검색 필드와 관리형 동의어 사전으로 시작한다. 영문 대소문자·공백·하이픈·유니코드 정규화를 처리하고 한글 조합 중에는 검색 요청을 확정하지 않는다. 정확한 명칭, 별칭, 구절·동작, 설명 순으로 가중치를 둔다. 검색어 토큰 순서가 달라도 매칭하며 모호한 입력에 단일 정답을 강요하지 않는다.

결과에 매칭 근거를 표시한다. 예: `동작 설명 일치: 아래에서 올라옴`. 임의의 자연어 문장 전체를 이해하는 기능으로 과장하지 않는다. 무결과에서는 추천 동작 태그, 검색 초기화, 관련 용어를 제공한다. 오타 교정·초성·의미 검색은 실제 검색 평가에서 필요성이 확인되면 추가한다.

### 상세 모달

상단에는 명칭 세트, 별칭, 주제·유형, 적용 환경, 한 문장 정의를 둔다. 본문은 `직접 체험 / 사용 가이드 / 직무별 가이드 / 코드 / 대체 UI와 출처`로 나눈다. PC에서는 데모와 설명을 나란히, 모바일에서는 데모 위·설명 아래의 전체 화면 모달로 제안한다. 화면 설계 단계에서 탭 수와 스크롤 길이를 확인한다.

체험에는 직접 조작, 초기화, PC·모바일 폭 선택, 상태·옵션 조절을 제공한다. 화면 폭 전환은 레이아웃 미리보기이며 실제 터치·키보드·모바일 브라우저 검증을 대신하지 않는다. 입력 컴포넌트는 기본·오류·비활성 상태, 데이터 UI는 로딩·빈 결과·오류·정상 상태를 필요한 범위에서 제공한다.

모달은 진입 시 내부로 포커스를 옮기고, 배경 조작을 막고, Tab 이동을 관리하며, 닫으면 호출 카드로 포커스를 복원한다. Esc와 닫기 버튼을 지원한다. 이는 [W3C 모달 패턴](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)에 근거한다. 상세 안의 모달 데모는 별도 데모 문서로 격리해 외부 상세창까지 닫히거나 배경을 가리는 충돌을 방지한다. 내부 Esc가 데모만 닫는지 별도 검증한다.

`/terms/[slug]`의 개별 URL도 제공한다. 목록에서 진입하면 모달, URL 직접 진입·새로고침에서는 같은 콘텐츠를 단독 상세로 표시한다. 닫기·브라우저 뒤로 가기에서 검색조건과 스크롤 위치가 복원되어야 한다.

### 직무별 내용

| 직무 | 포함할 내용 |
| --- | --- |
| 기획자 | 선택 이유, 진입·종료 조건, 사용자 흐름, 데이터·권한·실패 정책, 기획서에 적을 항목 |
| 디자이너 | 구조와 위계, 상태별 디자인, 전환, 포커스 표시, 작은 화면 대안, 접근성 |
| 퍼블리셔·프론트엔드 | 시맨틱 HTML, 키보드·포커스·ARIA, 반응형, CSS·JS, 상태와 이벤트 |
| 개발자 | 데이터 계약, API 연결 지점, 비동기·중복 요청·오류·취소 처리, 권한, 테스트 항목 |

같은 주의사항을 네 번 반복하지 않고 공통 원칙과 직무별 책임을 구분한다. 모든 UI가 API나 백엔드를 필요로 하지는 않으므로 해당하지 않는 항목에는 그 이유를 적는다.

### 코드

`HTML·CSS·JavaScript`와 `React·TypeScript`를 선택하면 대응하는 실제 데모와 코드가 함께 전환된다. 기본 코드는 바로 실행 가능한 전체 예제이고, 필요한 경우 핵심 부분만 별도로 설명한다. 파일별 복사·전체 복사, 복사 성공·실패 안내, 의존성과 실행 방법, 예제 버전을 제공한다.

실행 파일과 보여주는 코드의 원본을 같은 데모 패키지에서 가져온다. 두 언어 형식은 별도 구현하되 공통 동작 명세로 검증한다. 사이트 전용 import나 보이지 않는 전역 CSS가 없도록 독립 실행을 확인한다. 체험 옵션을 바꾸면 코드도 같은 설정으로 바꾸며, 오류·로딩 같은 일시적인 체험 상태는 코드 설정과 구분한다.

## PC 모바일 및 대안 정책

PC·모바일의 지원 여부를 각각 저장하고 `PC·모바일 공통 / PC 전용 / 모바일 전용 / 환경 제약`으로 표시한다. 전용 표시는 실제 제약 근거가 있을 때만 사용한다. 추가로 `마우스 / 키보드 / 터치`, 화면 폭 제약, 브라우저 조건을 기록한다. 모바일에서 흔하다는 이유만으로 모바일 전용이라고 표시하지 않는다. 특정 입력 방식에만 의존하는 데모에는 제한과 대안을 명시한다. [MDN hover 문서](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/hover)는 기기 이름보다 입력 기능을 확인할 근거다.

| 상황 | 제안 대안 | 조건 |
| --- | --- | --- |
| 호버 툴팁을 터치에서 사용 | 설명 텍스트 노출, 도움말 버튼과 팝오버 | 필수 정보는 호버에만 숨기지 않음 |
| 넓은 화면의 분할 보기 | 목록·상세 화면 전환 | 뒤로 가기와 선택한 항목 보존 |
| 큰 데이터 테이블 | 핵심 열 우선, 가로 스크롤, 행 상세 보기 | 행·열 비교가 중요하면 단순 카드 변환을 피함 |
| 드래그 정렬 | 위·아래 이동 버튼, 위치 선택 | 터치·키보드에서 같은 결과 제공 |
| 스와이프 액션 | 항상 보이는 메뉴 또는 액션 버튼 | 삭제 등 주요 기능을 제스처에만 숨기지 않음 |
| 당겨서 새로고침 | 새로고침 버튼 | 브라우저 기본 제스처와 충돌 검토 |
| 작은 화면의 보조 레이어 | 바텀시트 또는 전체 화면 대화상자 | 과업 길이·포커스·가상키보드에 따라 선택 |

대안에는 연결된 용어, 적용 조건, 장단점, 체험 링크를 저장한다. 단일 대안을 모든 상황의 정답으로 제시하지 않는다. [WCAG 드래그 기준](https://www.w3.org/WAI/WCAG22/Understanding/dragging-movements.html)에 따라 드래그에는 비드래그 포인터 대안도 제공한다. 키보드 지원만으로 이를 충족했다고 간주하지 않는다.

## 관리자 기능

`/admin`에서 용어, 카테고리, 태그·별칭, 관계·대안, 출처, 데모 연결, 변경 이력, 가져오기·내보내기를 관리한다. 개발자가 운영하더라도 콘텐츠 수정에 소스코드 직접 변경을 강제하지 않는다.

| 기능 | 동작 규칙 |
| --- | --- |
| 등록·편집·복제 | 전체 콘텐츠, 직무별 안내, 기기 조건, 코드·데모 연결을 편집. 복제본은 초안으로 생성 |
| 저장·게시 | 초안 저장과 게시 분리. 게시 중인 항목 편집은 새 초안으로 보존하고 명시적 게시 때만 반영 |
| 숨김·재노출 | 목록·검색·직접 상세 조회에서 모두 제외. 관리자 미리보기에서는 확인 |
| 순서 이동 | 전체 기본 순서와 카테고리 안 순서를 따로 관리. 드래그와 위·아래 이동 모두 제공 |
| 카테고리 변경 | 대표 카테고리 변경과 대상 카테고리 순서 반영을 한 트랜잭션으로 처리 |
| 카테고리 관리 | 추가·수정·숨김·이동·삭제. 사용 중 카테고리는 대체 분류를 지정한 후 삭제 |
| 카테고리 숨김 | 해당 카테고리의 용어도 열람 목록·검색·직접 조회에서 제외. 관리자에 영향 개수 표시 |
| 태그·별칭 관리 | 추가·수정·병합·삭제, 모호한 통칭과 진짜 동의어 구분 |
| 삭제·복원 | 휴지통 이동, 복원, 명시적 영구 삭제. 관련 용어·대안 연결 영향 표시 |
| 변경 이력 | 콘텐츠 리비전, 게시 이력, 분류·정렬 이력을 기록. 복원은 새 리비전 생성 |
| 일괄 변경 | 선택한 항목의 숨김·복원·카테고리 변경, 대상 개수와 실패 원인 표시 |
| 백업·이전 | 버전이 포함된 JSON 내보내기·검증 후 가져오기, 별도 DB 백업·복구 절차 |

숨김·휴지통 항목을 관련 용어·대안에서 추천하지 않는다. 대안 항목을 숨기거나 삭제할 때 연결 영향을 보여주고 대체 설명을 보완하도록 한다. 기본 순서를 바꿔도 검색 관련도 정렬은 바뀌지 않는다. 필터된 관리자 목록에서 순서를 옮기면 어느 순서를 수정하는지 표시한다.

동시에 열린 관리자 탭의 덮어쓰기를 방지하기 위해 저장에 리비전 번호를 포함한다. 충돌 시 마지막 저장본과 비교하며 조용히 덮어쓰지 않는다. 잘못된 입력, 저장 중, 실패, 재시도와 저장되지 않은 변경 안내도 설계한다.

## 구현 제안

### 로컬 기술 구성

| 계층 | 제안 | 이유 |
| --- | --- | --- |
| 화면·서버 | Next.js App Router, React, TypeScript, Node.js 런타임 | 목록·상세·관리자와 서버 API를 한 프로젝트로 유지 |
| 영구 저장 | SQLite, 마이그레이션, 데이터 접근 계층 | 별도 DB 서버 없이 로컬 콘텐츠와 순서를 저장 |
| 스키마·검증 | Drizzle 계열 스키마 및 Zod 계열 입력 검증 검토 | 타입과 서버 검증의 일관성, SQLite 지원 |
| 스타일·모션 | CSS 변수·모듈, 실제 조작은 CSS transition·animation 우선, 시연 제어는 공통 시계와 필요 시 Web Animations API | UI 원리 설명·코드 복사와 전체 재생·일시정지를 함께 지원 |
| 데모 | 등록된 데모 패키지와 격리된 preview 문서 | 코드·스타일·모달·스크롤의 충돌 방지 |
| 테스트 | 의미 있는 로직 테스트, 핵심 흐름 E2E, 접근성 수동 점검 | 검색·영구 저장·체험·복사 등 실제 요구 검증 |

버전과 SQLite 드라이버는 구현 시 로컬 Node 환경 및 공식 지원 범위를 확인한 뒤 고정한다. [Next.js Route Handlers](https://nextjs.org/docs/app/getting-started/route-handlers)를 서버 API 구성 근거로 확인했다. DB는 브라우저 localStorage로 대체하지 않는다. localStorage는 움직임 설정 같은 기기별 선호에만 사용한다.

로컬 서버는 127.0.0.1에 바인딩하는 단일 운영자 모드로 시작하는 안이다. 변경 API의 Host·Origin 및 입력을 서버에서 검증한다. 공개용 로그인·다중 운영자 권한은 공개 전 별도 단계에서 설계한다. 공개 서버에 로컬 운영자 모드가 그대로 실행되지 않도록 시작 조건을 분리한다. 이는 외부 공개 결정이 없는 현재 범위에 맞춘 제안이다.

향후 고정 디스크가 있는 단일 Node 서버라면 SQLite 유지도 검토할 수 있다. 다중 인스턴스·서버리스 환경이면 PostgreSQL 등 외부 DB 이전을 검토한다. 저장 계층을 분리하되 자동 무수정 이전을 보장하지 않는다. Codex Sites를 나중에 선택하면 해당 런타임·D1 저장·인증 방식에 맞는 별도 검토가 필요하다.

### 저장 모델과 코드의 책임

| 모델 | 주요 필드·관계 |
| --- | --- |
| Term | 고정 ID, slug, 상태, 대표 카테고리, 전체 순서, 카테고리 순서, 현재 초안·게시 리비전 ID |
| TermRevision | 영문·발음·한국어, 요약·설명, 직무별 안내, 사용·금지 상황, 기기 조건, demo ID·버전·옵션, 변경일 |
| Category | 이름, 설명, 순서, 노출 상태 |
| Tag 및 Alias | 표시명, 정규화 검색어, 관계 종류, 용어 연결 |
| TermRelation | 동의어·변형·관련·비교·대안, 대상 ID, 조건·이유 |
| Source | 제목, URL, 출처 종류, 확인일, 근거 범위, 검토 상태 |
| ChangeLog | 등록·게시·숨김·분류·이동·삭제 이력과 대상 리비전 |
| DemoManifest | 코드에서 관리하는 demo ID, 버전, 두 형식의 실행·코드 파일, 설정 스키마, 지원 입력 방식 |

본문은 DB가 원본이다. 초기 데이터 파일은 처음 등록할 때만 사용하며 서버 재시작·업데이트가 관리자 편집을 덮어쓰면 안 된다. 실행 동작은 코드가 원본이다. 관리자에서는 등록된 demo ID와 검증된 옵션을 연결한다. 새 동작 추가는 개발자가 데모 파일·설정·테스트를 등록한 뒤 관리자에서 용어와 연결한다.

관리 화면에 입력한 임의 JS를 사이트 권한으로 실행하지 않는다. 코드 예제를 자유롭게 수정하는 경우 실행 가능한 버전과의 일치 검증을 거쳐 게시한다. 게시 리비전이 참조하는 데모 버전이 없거나 두 코드 형식이 누락되면 게시를 막고 원인을 표시한다.

DB 외래키로 분류·관계 무결성을 유지한다. 순서·분류·상태 변경은 트랜잭션으로 저장한다. 게시 시 해당 조회 캐시와 검색 데이터를 함께 갱신하며 실패 시 불완전한 성공으로 표시하지 않는다. 이전 slug는 리다이렉트 관계로 보존한다.

데모는 허용한 로컬 자산만 읽는 별도 문서에서 실행하고 관리자 쓰기 API를 호출하지 않는다. iframe의 sandbox·CSP와 필요한 postMessage 명령을 명시한다. 메시지는 허용 명령·payload·발신 프레임을 검증한다. iframe 내부 키보드에서 바깥으로 이동할 경로와 제목을 제공한다. 모든 데모를 처음부터 iframe으로 마운트하지 않고 상세 열기·명시적 체험 때 로드한다.

백업은 JSON 콘텐츠 내보내기와 DB 일관성 백업을 구분한다. 실행 중 DB 파일 하나만 임의 복사하지 않고 [SQLite Backup API 또는 VACUUM INTO](https://www.sqlite.org/backup.html)를 검토한다. 복구 검증은 새 임시 DB에서 진행한다. DB·백업·로컬 비밀 값은 소스 저장소에 커밋하지 않는다.

## 대표 상세 원고와 데모 명세 예시

대상: `Modal Dialog / 모달 다이얼로그 / 모달 대화상자`.

- 정의: 현재 화면 위에서 별도의 작업을 진행하게 하고, 닫기 전까지 배경 조작을 제한하는 대화상자. 근거는 [W3C APG](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/).
- 사용 상황: 현재 흐름과 직접 관련된 짧은 정보 확인·선택·입력. 긴 편집은 별도 화면 대안을 함께 제시한다.
- 통칭 태그: 모달, 레이어 팝업. 팝업은 더 넓은 의미의 통칭이라는 설명을 붙인다.
- 데모: 열기 → 내부 컨트롤 조작 → 닫기 버튼 또는 Esc → 호출 버튼으로 포커스 복원. 배경 클릭 닫기는 선택 옵션으로 비교한다.
- 상태: 닫힘·열림, 짧은 내용·긴 내용, 작은 화면. 중첩된 서비스 모달은 기본 사용 예로 권장하지 않는다.
- 기획자: 왜 흐름을 중단하는지, 닫을 수 있는 조건, 작성 중 데이터의 보존·폐기 정책을 정의한다.
- 디자이너: 제목·본문·행동 위계, 최대 높이와 스크롤, 초점 표시, 좁은 화면에서의 전체 화면 전환을 정한다.
- 퍼블리셔: 시맨틱 dialog, 접근 가능한 이름, 초기 초점, 배경 inert, 포커스 복원·스크롤 처리를 구현한다.
- 개발자: 열림 상태와 작업 상태를 분리한다. 비동기 저장 중 닫기·취소·실패·중복 실행 정책을 정의한다.
- 환경: PC·모바일 공통. 복잡한 입력이 길어지면 별도 페이지, 짧은 모바일 선택은 바텀시트를 대안으로 검토한다.
- 코드: 자체 작성한 두 형식 예제. 프레임워크 예제와 바닐라 예제에 같은 동작 검증표를 적용한다.

이 예시는 원고·체험 형식의 기준이며 구현되거나 실기기 검증된 데모가 아니다.

| 2 콘텐츠·화면 설계 | 대표 6개 상세 원고·정지 장면·전후 스토리보드, 목록·상세·관리자 와이어프레임 | UI 형태·동작 의미·직무 안내·코드·대안의 정보 위계 확인 |
| 3 공통 기반 | DB·관리자 CRUD·검색·모달·데모 실행 구조 | 재시작 후 데이터 보존, 숨김·삭제·순서·분류와 직접 URL 규칙 통과 |
| 4 대표 데모 검증 | 모달, 아코디언, 콤보박스, 스켈레톤, 데이터 그리드, 바텀시트 | 두 코드 형식, 키보드·좁은 화면·초기화·격리 검증 통과 |
| 5 콘텐츠 확장 | 최종 40~60개 완성 | 모든 항목에 필수 원고·실행 데모·두 코드·출처·환경 안내 충족 |
| 6 로컬 인수 | 실행 안내, 백업·복구 안내, 검증 결과 | [검토 계획](qa-plan.md)의 필수 시나리오 통과 |
| 추후 공개 | 배포·로그인·접근 정책·영구 저장 운영안 | 사용자가 공개 범위와 환경을 결정한 뒤 별도 진행 |

6개 대표 데모로 기반을 확인하는 단계는 중간 검증이며, 첫 출시의 최종 범위 40~60개를 대체하지 않는다. 공개 배포, 사용자 계정·즐겨찾기·댓글, 비개발자용 동작 제작 도구, iOS·Android 네이티브 코드 예제는 현재 범위에 포함하지 않는다. 웹에서 재현한 동작이 네이티브 플랫폼 동작과 다른 부분은 원고에 명시한다.

관리자 화면은 다크 테마 전용으로 디자인한다. 배경·입력 필드·표·모달·메뉴·선택·오류·비활성·포커스 상태에 일관된 다크 색상 체계를 적용한다. 운영체제의 라이트 테마 설정에서도 관리자 다크 테마를 유지한다. 관리자 전용 스타일은 프론트와 데모의 스타일에 영향을 주지 않도록 분리한다.

프론트 화면은 [우디디자인랩 UI 미니 사전](https://woodydesignlab.com/ui/dict)을 기준으로 밝은 회색 배경·흰색 둥근 카드·파란 강조색·큰 검색창·가로 카테고리 칩·UI 동작 미리보기를 적용한다. PC에서도 좁은 2열을 유지하는 원본과 달리, 사용자가 선택한 넓은 3~4열 구성을 사용한다. 모바일은 카드형 인상을 유지한다. 상세 모달은 같은 밝은 시각 체계로 별도 설계한다. 관찰한 디자인과 새롭게 제안하는 확장 규칙은 [디자인 적용안](design-reference.md)에 구분해 기록했다. 관리자 다크 테마는 프론트와 독립적으로 적용한다.

이 기획안의 다음 작업은 확정된 참고 디자인과 PC 배치를 반영한 대표 원고·와이어프레임 설계다. 비교가 쉬운 일관된 데모 무대와 실무 참고에 적합한 정보 위계를 유지한다.

UI 이미지·모션의 제작 방식과 60개 동작 명세를 먼저 검토하고, 대표 상태·스토리보드 시안에서 형태를 확인한 후 동작 프로토타입으로 넘어간다. 문서 명세가 완성됐다는 사실을 실제 이미지·애니메이션 품질 검증 완료로 간주하지 않는다.
