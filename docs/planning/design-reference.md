# 프론트 참고 디자인 적용안

기준일: 2026-11-26. 사용자 지정 참고는 [우디디자인랩 UI 미니 사전](https://woodydesignlab.com/ui/dict)이다. 사용자가 전달한 링크의 utm 매개변수는 디자인 기준에 필요하지 않아 문서에는 본문 주소를 기록한다.

프론트는 참고 사이트의 밝은 배경·둥근 카드·파란 강조·검색 중심 구조를 따른다. PC 목록은 사용자가 선택한 넓은 3~4열로 확장하고 관리자 화면은 다크 테마 전용으로 설계한다. 아래에서 실제 관찰과 이번 프로젝트에 제안하는 수치를 구분한다.

## 확인한 화면과 동작

| 항목 | 참고 사이트에서 관찰한 내용 |
| --- | --- |
| 전체 배치 | 큰 화면에서도 중앙에 좁은 콘텐츠 영역을 둔다. 관찰한 상위 컨테이너의 max-width는 430px이며 카드 목록은 2열이다 |
| 배경·표면 | 밝은 회색 바탕에 흰색 카드와 검색 영역. 본문 body의 관찰된 배경색은 rgb(243, 244, 246) |
| 강조 | 제목 일부와 데모 UI에 파란색을 사용. 제목의 강조 부분에서 rgb(47, 134, 246)을 확인 |
| 제목 | 짧은 두 줄 소개. 관찰된 h1은 25px, weight 800, line-height 33px |
| 검색 | 둥근 흰색 검색 영역, 돋보기, 생김새로도 찾을 수 있다는 안내, 추천 검색 버튼 |
| 카테고리 | 가로 칩 탐색. 선택된 칩은 rgb(30, 30, 33) 배경·흰색 글자·99px radius로 관찰 |
| 카드 | 흰색 둥근 외곽, 별도 회색 테두리 느낌의 데모 무대, 짧은 한국어 이름과 영문 이름 |
| 미리보기 | 토스트·모달·바텀시트 등 축소 UI에서 상태가 변화하는 애니메이션 |
| 결과 영역 | 카테고리명 또는 검색 결과 제목과 항목 개수 |
| 글꼴 | body의 계산된 font-family에서 Apple SD Gothic Neo를 확인. 다른 운영체제 결과는 확인하지 않음 |

브라우저에서 추천 검색어를 누르면 검색창에 해당 문구가 입력되고 결과가 바뀌는 것을 확인했다. `아래에서 올라오는 창`은 바텀시트 1개로 좁혀졌고 지우기 버튼으로 목록이 복원됐다. 움직임 카테고리를 선택하면 해당 카테고리가 활성화되고 모션 예시 목록으로 바뀌었다.

1280px 및 390px 뷰포트에서 렌더링을 확인했다. 작은 화면에서는 검색 추천어 줄바꿈·가로 카테고리·2열 카드 구성을 확인했다. 이는 데스크톱 브라우저의 폭별 관찰이며 모바일 실기기 테스트는 아니다. 임시 뷰포트 설정은 관찰 후 해제했다.

확인한 범위는 공개 목록·검색·카테고리·데모 미리보기다. 참고 사이트의 상세 가이드·관리자·코드 체험 구조를 확인한 것으로 간주하지 않는다. 해당 기능은 사용자 요구에 맞춰 새로 설계한다.

## 프론트 적용 규칙

### 화면 구조

1. 작은 브랜드 헤더와 얇은 구분선.
2. 짧은 소개 제목과 핵심 단어의 파란 강조.
3. 충분한 높이의 검색창과 동작 표현 추천 버튼.
4. 가로 카테고리 칩, 유형·지원 환경의 보조 필터.
5. 선택한 주제 또는 검색 결과 제목, 결과 수, 정렬.
6. 애니메이션 무대를 중심으로 구성한 카드 그리드.
7. 페이지네이션과 간단한 하단 안내.

참고 사이트의 좌우 여백·둥근 표면·검은 선택 칩·파란 포인트를 유지하면서 실무 정보가 읽히도록 카드 크기와 정보량을 조정한다. 기존 기획의 좌측 고정 카테고리 메뉴는 상단 칩 탐색으로 대체한다.

### 폭과 밀도 제안

| 화면 조건 | 제안 |
| --- | --- |
| 넓은 PC | 최대 콘텐츠 폭 약 1120~1200px, 기본 4열 |
| 중간 PC | 카드 가독성에 따라 3열 |
| 태블릿·모바일 | 기본 2열, 카테고리는 가로 스크롤 |
| 매우 좁은 폭·확대 글자 | 카드 최소 가독 폭이 부족하면 1열 |
| 상세 | PC는 넓은 모달의 데모·설명 병렬, 모바일은 전체 화면의 세로 흐름 |

픽셀 단위 브레이크포인트는 와이어프레임에서 실제 제목·세 명칭·태그·요약이 들어간 상태로 결정한다. 참고 사이트의 430px 컨테이너를 PC에 그대로 적용하지 않는다. 모바일 2열을 유지하려고 필수 글자나 조작 대상을 과도하게 줄이지 않는다.

### 카드 구성

데모 무대 → 영문 명칭·한국어 발음·한국어 표현 → 짧은 사용 상황 → 별칭 태그 → 환경 표시 순으로 배치한다. 세 명칭의 위계와 줄 수는 대표 카드 원고로 비교하되 세 항목을 모두 확인할 수 있어야 한다. 긴 태그는 추가 개수 표시와 상세 연결로 정리하며 필수 의미를 잘라내지 않는다.

흰색 표면과 큰 둥근 모서리, 여유 있는 무대, 파란 상태 강조를 사용한다. 상세 열기와 미리보기 재생 버튼을 분리한다. 자동 재생은 기존 기획의 동시 최대 2개·화면 밖 정지·재생 제어·모션 감소 정책을 따른다. 작은 화면에서 카드 수가 늘어도 모든 데모를 동시에 무한 재생하지 않는다.

카드 안 이미지는 HTML·CSS·SVG로 만든 대표 상태다. 320×200 논리 크기의 8:5 미리보기 무대를 시작안으로 두고, 상세 체험은 가독성 있는 실제 크기로 다시 배치한다. 장면·시연·상태 전환은 [이미지와 애니메이션 구현 계획](visual-motion-plan.md)과 [UI별 명세](ui-motion-specs.md)를 따른다. 이 비율은 참고 사이트에서 추출한 규격이 아니라 본 프로젝트의 제안이다.

### 색상과 타이포그래피 제안

| 역할 | 프로젝트 제안 |
| --- | --- |
| 페이지 배경 | #F3F4F6 계열의 밝은 회색 |
| 카드·모달 표면 | #FFFFFF |
| 기본 글자 | #18181B 계열 |
| 보조 글자 | #52525B 계열 |
| 장식·제목 강조 | 참고에서 확인한 #2F86F6 계열 |
| 흰 글자 버튼·작은 링크 | 같은 파란 계열의 더 짙은 색을 검토하고 실제 대비 확인 |
| 선택 카테고리 | #1E1E21 계열 배경과 흰색 글자 |
| 본문 | 16px 이상을 기본으로 유지 |
| 레이블·별칭 | 14px 이상을 기본으로 유지 |
| 소개 제목 | PC 32~40px, 모바일 26~30px를 시작안으로 비교 |
| 외곽 모서리 | 카드 약 20~24px, 데모 무대 약 12~16px, 칩은 pill 형태 |

표의 값은 구현 시작안이다. 관찰값을 적은 첫 표와 달리 프로젝트에서 검증·조정할 수 있다. 글꼴은 한국어 가독성과 로컬 재현성을 고려한 시스템 글꼴 스택을 우선 검토한다. 폰트 파일 사용이 필요해지면 배포 조건과 라이선스를 확인한다.

### 상세 모달 확장

목록과 같은 밝은 배경 체계·둥근 표면·검은 제목·파란 상호작용 강조를 사용한다. 상단에 명칭과 환경을 두고, 직접 체험·사용 가이드·직무별 안내·코드·대안으로 내용을 구성한다. 코드 블록은 코드 가독성에 맞춰 별도 표면을 쓸 수 있지만 프론트 전체를 관리자 다크 테마로 바꾸지 않는다.

실제 체험과 애니메이션 감상을 구분하고 현재 조작 가능한 컨트롤을 명확하게 표시한다. 원본의 축소 데모를 큰 화면에 단순 확대하는 대신 키보드·마우스·터치 및 오류 상태를 확인할 수 있는 체험 무대를 설계한다.

## 관리자 다크 테마

전체 배경은 #09090B~#101014, 표면은 #18181B~#202026, 기본 글자는 #FAFAFA 계열을 시작안으로 검토한다. 표·입력·선택·메뉴·팝업·오류·비활성·초점 상태를 같은 다크 체계로 만든다. 구분은 미세한 명도·테두리·간격을 함께 사용하고 색 하나에만 상태를 맡기지 않는다.

운영체제 설정과 무관하게 다크로 유지한다. 관리자 네비게이션·표 밀도·편집 폼은 반복 운영에 맞춰 설계하며, 프론트의 카드형 탐색을 관리자 목록에 그대로 강제하지 않는다. 프론트와 공유하는 데이터·검증 로직은 유지하되 테마·표면 스타일은 독립시킨다.

## 시안 검토 순서

대표 원고가 들어간 PC 4열 목록, 중간 폭 3열 목록, 모바일 2열 목록, 상세 모달, 관리자 용어 목록·편집 화면을 우선 설계한다. 대표 데모의 구조와 코드 표시는 [전체 기획안](README.md), 검토 기준은 [검토 계획](qa-plan.md)을 따른다.

밝은 목록에서 실무 정보가 과밀하지 않은지, 상단 칩이 8개 주제 탐색에 충분한지, 짧은 미리보기로 해당 UI를 구별할 수 있는지, 관리자 다크 화면에서 표·폼 상태가 읽히는지를 확인한다.
