# UI 용어 사이트 검토 계획

상태: 구현 전 검증 명세. 아래 항목은 아직 실행한 테스트 결과가 아니다. 필수 요구를 통과해야 로컬 인수를 완료하며, 6개 대표 데모 검증 이후 최종 40~60개에도 같은 기준을 적용한다.

## 요구사항과 통과 기준

| ID | 검토 항목 | 방법 | 통과 기준 |
| --- | --- | --- | --- |
| Q01 | 용어 내용과 명칭 | 원고 수동 검수 + 필수 필드 검증 | 영문·발음·한국어·사용 상황·별칭 관계·직무 안내·출처·확인일 누락 없음 |
| Q02 | 용어 검색 | 고정 검색 집합의 자동 평가 | 정확한 명칭은 해당 용어가 1위. 별칭·동작은 아래 기대 결과를 상위 3개에 포함 |
| Q03 | 조합형 검색 | 입력 흐름 E2E | 한글 IME 조합 중 확정 검색·포커스 이동 없음. 공백·대소문자·필터 조합과 무결과 정상 |
| Q04 | 목록 동작 예시 | 대표 카드와 전체 목록 수동 확인 | 의미 있는 상태 전환, 재생·정지·재생 종료, 카드 열기와 재생 버튼 충돌 없음 |
| Q05 | 상세와 URL | 목록·직접 주소·새로고침·뒤로 가기 E2E | 모달과 단독 상세 내용 일치. 목록 검색·필터·스크롤 보존 |
| Q06 | 모달 포커스 | 키보드 수동 + E2E | 초기 초점·Tab 순환·배경 비활성·Esc·닫기 후 복원 정상 |
| Q07 | 상세 안 데모 격리 | 모달·드로어·캐러셀·스크롤 데모 조작 | 내부 동작이 외부 상세를 닫거나 덮지 않음. 내부 Esc와 외부 닫기 역할 명확 |
| Q08 | 실제 시뮬레이션 | 각 용어 동작 명세 수동/E2E | 정해진 상태·입력·실패·초기화가 동작. 장식 애니메이션만으로 체험을 대체하지 않음 |
| Q09 | 두 코드 예제 | 별도 깨끗한 실행 환경에서 예제 실행 | HTML·CSS·JS와 React·TS 모두 실행되고 대응 데모와 동일하게 동작 |
| Q10 | 코드 복사 | 파일별·전체 복사·권한 실패 테스트 | 필요한 파일·import·스타일·의존성 누락 없음. 실제 클립보드 내용 일치, 실패 안내 |
| Q11 | 추가·편집·게시 | 관리자 → 사용자 화면 흐름 E2E | 초안이 게시본을 덮지 않음. 게시 시 목록·상세·검색·태그가 함께 갱신 |
| Q12 | 숨김·휴지통 | 목록·검색·직접 URL·관계 조회 검사 | 비노출 항목이 열람 API·관련 추천·직접 상세에 새지 않음. 관리자 미리보기만 허용 |
| Q13 | 순서·분류 | DB 통합 테스트 + 재시작 후 조회 | 전체 순서·분류 내 순서가 독립 유지. 중복/누락·분류 고아 없음 |
| Q14 | 카테고리·태그 관리 | 사용 중 분류 삭제·숨김·태그 병합 시나리오 | 영향 개수 안내, 재분류 후 삭제, 숨긴 분류의 용어 비노출, 검색/관계 일관성 |
| Q15 | 삭제·복원·영구 삭제 | 의존 관계가 있는 항목으로 통합 테스트 | 휴지통 복원 가능, 영구 삭제 조건과 영향 명확, 끊어진 대안 안내 정리 |
| Q16 | 영구 저장 | 생성·편집·정렬 → 서버 종료 → 재실행 | 콘텐츠·순서·분류·상태·리비전이 동일하고 초기 데이터가 덮어쓰지 않음 |
| Q17 | 동시 편집·저장 실패 | 두 관리자 탭·실패 주입 | 리비전 충돌 감지, 실패 데이터 부분 반영 없음, 재시도 가능 |
| Q18 | 백업·가져오기·복구 | 새 임시 DB로 내보내기·복원 비교 | 용어·태그·관계·순서·상태·리비전 수와 값 보존. 잘못된 파일은 적용 전 거부 |
| Q19 | 환경과 대안 | PC·모바일·입력 방식 수동 확인 | 제약 표시 정확, 필요한 항목에 대안·이유·연결·동작 제공 |
| Q20 | 접근성·모션 감소 | 자동 검사 + 키보드 + 스크린리더 수동 | 접근 가능한 이름·오류 안내·초점·확대·읽기 순서 확인. 모션 감소·전체 정지 적용 |
| Q21 | 목록 성능 | 60개 후보 상당 콘텐츠로 측정 | 상세 데모가 일괄 로드되지 않음. 화면 밖 동작 정지, 동시 카드 재생 제한 준수 |
| Q22 | 로컬 경계·입력 검증 | 다른 Origin·잘못된 ID·스키마·demo ID 요청 | 로컬 단일 운영자 모드의 변경 요청 검증. 임의 JS·잘못된 demo 연결 게시 거부 |

## 대표 데모별 확인

| 데모 | 핵심 검토 |
| --- | --- |
| 모달 | 포커스 진입·복원, Esc, 배경 조작 차단, 긴 내용, 외부 상세 모달과 분리 |
| 아코디언 | Enter·Space, expanded 상태, 단일/복수 펼침, 내용 재배치 |
| 콤보박스 | 직접 입력·선택, IME, 추천 목록, 방향키·Enter·Esc, label·선택 상태 |
| 스켈레톤 | 로딩에서 콘텐츠 전환, 실패·빈 상태 구분, 모션 감소, 반복 읽기 방지 |
| 데이터 그리드 | 표와 다른 복합 키보드 이동, 편집 진입·종료, 셀 포커스, 좁은 화면 대안 |
| 바텀시트 | 열기·닫기·가상키보드·스크롤, 비드래그 대안, 작은 화면과 웹 재현 한계 |

모든 최종 데모는 최소한 기본 동작, 사용자의 입력 방식, 다시 시작, 대응 코드의 독립 실행을 확인한다. 서로 다른 컴포넌트에 하나의 범용 애니메이션만 바꿔 넣어 통과시키지 않는다.

## 브라우저 화면과 접근성

- 관리자 화면은 운영체제의 라이트·다크 설정 모두에서 다크 테마를 유지하는지 확인한다. 입력·표·모달·메뉴·선택·오류·비활성·포커스 상태의 대비와 가독성, 관리자 스타일의 프론트·데모 유출 여부를 점검한다.
- 프론트는 [우디디자인랩 UI 미니 사전](https://woodydesignlab.com/ui/dict)의 회색 배경·흰색 카드·파란 강조·검색 중심 구성과 [디자인 적용안](design-reference.md)을 비교한다. 사용자가 선택한 PC 3~4열 확장, 모바일 기본 2열 및 좁은 폭·글자 확대 시 1열 전환을 확인한다.
- 주제 칩의 가로 탐색·선택·키보드 포커스, 검색 추천어 적용·초기화, 카드의 세 명칭·요약·태그·기기 표시가 목록 밀도 속에서도 읽히는지 확인한다. 참고 사이트의 좁은 PC 2열을 재현하는 것을 합격 조건으로 삼지 않는다.
- 360·390·768·1280·1440 CSS px를 시작 점검 폭으로 사용하되 특정 기기에만 맞춰 구현하지 않는다.
- Chrome·Safari·Firefox의 검증 시점 안정 버전을 기록한다. 모바일은 iOS Safari·Android Chrome을 최소 대상안으로 둔다.
- 로컬 PC의 폭 축소는 화면 배치 검증이다. 실기기 터치·가상키보드·브라우저 제스처 검증과 구분해서 결과를 기록한다.
- 실제 모바일 검증에 사용할 기기·안전한 접속 방식은 구현 단계에서 확인한다. 현재 로컬 전용 선택을 네트워크 공개 허가로 해석하지 않는다.
- 모든 조작을 키보드로 확인하고 macOS VoiceOver 등 이용 가능한 보조기술로 수동 점검한다. 자동 검사만으로 접근성을 확정하지 않는다.
- 글자 200% 확대, 필요한 재배치 조건, 색에만 의존하는 상태, 초점 가림, 설명·오류 연결, 드래그와 스와이프의 대안을 확인한다.
- 모션 감소 설정에서는 비필수 이동·확대를 제거하거나 정적인 비교로 바꾼다. 사용자가 명시적으로 재생하는 경우에도 정지 경로를 제공한다.

## 성능 측정안

검색 입력 확정부터 화면 갱신까지 로컬 60개 데이터 기준 100ms 이내를 초기 목표로 둔다. 숫자는 제안 목표이며 측정 환경·브라우저·하드웨어를 함께 기록한다. 한글 조합 완료와 debounce 시간을 분리해 측정한다.

상세용 실행 코드를 지연 로드하고 화면 밖 타이머·관찰자를 정리하는지 확인한다. 10회 모달 열기·닫기 후 이벤트·타이머가 누적되지 않고 목록 스크롤이 유지되는지 점검한다. 허용 수준을 넘는 문제가 관찰됐을 때만 추가 최적화·반복 측정을 수행한다.

| M04 | 화면 밖·문서 숨김·상세 열림 후 복귀 | 동시 최대 2개·시계 정지·사용자 정지 우선. 오래 숨겨도 단계를 건너뛰지 않음 |
| M05 | 한 시나리오 10회 다시 보기 | 매번 같은 시작 데이터·전환·끝 상태. 포인터·타이머·모의 요청 누적 없음 |
| M06 | 처리 중 초기화·형식 변경·닫기 | 이전 실행의 늦은 완료가 새 실행 상태를 변경하지 않음. 파일 선택·포인터 캡처도 정리 |
| M07 | 모션 감소·전체 움직임 끄기 | 자동 재생 없음. UI별 R0~R4 정적·단계·조작 대안 제공. 필수 정보를 잃지 않음 |
| M08 | 키보드·스크린리더로 목록 탐색 | 축소 무대 안 가짜 컨트롤은 focus·live 대상 아님. 설명·실제 재생 버튼만 읽힘 |
| M09 | 작은 카드·글자 확대·상세 비교 | 필수 이름·설명·조작은 읽을 크기. 상세를 단순 축소 이미지로 대체하지 않음 |
| M10 | 실제 선택기·파일·키보드 사용 | 네이티브 창을 가짜 애니메이션으로 오인시키지 않음. 실제 조작과 모의 처리의 경계 명확 |
| M11 | 바닐라·React 실행과 복사 비교 | 선택한 형식과 실제 코드 일치. 시연용 포인터·플레이어가 기본 복사 코드에 섞이지 않음 |
| M12 | 6개 복합 UI의 경계 상태 조작 | 모달 포커스·시트 드래그 대안·높이 변경·IME·그리드 편집·스켈레톤 실패 상태 정상 |

## 결과 기록

구현 후 각 검토는 `미실행 / 통과 / 실패 / 환경 제약으로 미확인`으로 기록한다. 실행한 버전·브라우저·데이터·증거·남은 문제를 남긴다. 지금 생성한 문서는 검토 계획이며 테스트를 통과한 결과표가 아니다.

인수에는 최종 40~60개 완성, 필수 흐름 통과, 재시작 영구 저장 확인, 백업 복구 확인, 실행 안내가 필요하다. 공개 배포 전에는 인증·서버 권한·영구 디스크·DB 이전·운영 백업·로그 등의 공개 환경 검토를 별도로 진행한다.
