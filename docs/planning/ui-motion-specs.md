# 60개 UI의 이미지와 동작 명세

상태: 구현 전 상세 설계안. [공통 제작·재생 규칙](visual-motion-plan.md)과 [60개 용어 후보](catalog.md)에 대응한다. 모든 시간·거리·예시 값은 프로젝트 시작안으로 시각·동작 검증 후 조정한다. 특정 디자인 시스템의 의무값으로 설명하지 않는다.

`대표 이미지`는 별도 그림 파일이 아니라 해당 장면을 코드로 그린 지정 상태다. `시연`은 목록에서 한 번 재생할 자동 순서이며 괄호는 전체 길이다. 아래 시간은 시연의 준비·읽기 대기와 별도로 실제 전환에 걸리는 시간이다. 직접 체험은 자동 시연과 동시 실행하지 않는다. R0~R4는 공통 문서의 모션 감소 프로필이다.

## 대표 6개 상세 스토리보드

이 절은 구현자가 장면과 전환을 바로 나눌 수 있도록 한 상세 설계다. 숫자는 검증 전 시작안이다. 시연에서 사용하는 포인터·하이라이트는 장식이고 실제 초점 이동은 상세 직접 체험에만 적용한다.

### C31 모달

장면은 배경의 설정 폼, 열기 버튼, 딤 레이어, 제목·본문·취소/적용·닫기를 갖는 대화상자다. 목록의 정적 대표 이미지는 열린 대화상자와 차단된 배경이다.

| 시간 | 상태·동작 |
| --- | --- |
| 0~600ms | 닫힌 상태와 열기 버튼을 보여줌 |
| 600~820ms | open 동작. backdrop은 160ms, dialog는 220ms로 진입 |
| 820~2100ms | 열린 상태 유지. 내부 적용 버튼에 시연 강조를 표시 |
| 2100~2280ms | close 동작. dialog opacity·작은 이동으로 180ms 퇴장 |
| 2280~3200ms | 배경에 적용 결과를 표시하고 종료 |

실제 체험의 상태는 closed·open과 별도의 idle·saving·error다. 열면 제목 또는 첫 유효 컨트롤로 초점을 옮기고 배경은 조작하지 못한다. Esc·닫기·취소·적용을 직접 확인한다. 배경 클릭 닫기는 옵션으로 비교하고 긴 입력의 폐기 정책을 설명한다. 저장 실패 시 모달을 유지하며 재시도 가능해야 한다. 모션 감소에서는 열고 닫기를 즉시 반영한다. 기능 기준은 [W3C Modal Dialog](https://www.w3.org/WAI/ARIA/apg/patterns/dialog-modal/)를 따른다.

### C36 바텀시트

장면은 모바일형 앱 목록, 열기 버튼, 딤, 하단 패널, 핸들, 3개 선택 행과 닫기 버튼이다. 기본 높이는 체험 영역 높이의 56%, 상단 모서리 20px를 시작안으로 둔다. 이 값은 해당 UI의 보편 규격이 아니다.

| 시간 | 상태·동작 |
| --- | --- |
| 0~600ms | 앱 목록과 열기 버튼 |
| 600~920ms | 패널을 자체 높이만큼 아래에서 translateY(100%→0), 딤은 180ms |
| 920~2400ms | 열린 상태, 선택 가능한 행을 강조 |
| 2400~2620ms | 행 선택 후 close, 220ms 퇴장 |
| 2620~3800ms | 배경의 선택 결과를 보여줌 |

기본 체험은 모달형이다. 열기/닫기 버튼은 항상 제공한다. 드래그는 핸들에서만 시작하고 시트 내용의 세로 스크롤과 구분한다. 아래로 끈 거리가 시트 높이의 25%를 넘거나 충분히 빠른 하향 release인 경우 닫는 시작안을 두고, 속도 임계값은 프로토타입에서 검증해 확정한다. 임계값 미만은 열린 위치로 220ms 복귀한다. 드래그 없이도 같은 결과를 얻을 수 있어야 한다. 화면 키보드와 긴 내용은 별도 시나리오로 확인한다.

### C27 아코디언

장면은 3개 heading 버튼과 각각 다른 길이의 본문이다. 대표 이미지는 두 번째 본문이 열린 상태다. 단일 펼침 모드의 기본 동작은 다음과 같다.

| 시간 | 상태·동작 |
| --- | --- |
| 0~600ms | 모두 닫힘 |
| 600~800ms | 첫 항목의 내용 높이를 0에서 측정 높이로 변경 |
| 800~1900ms | 첫 내용 읽기 |
| 1900~2100ms | 첫 항목 닫힘 180ms, 둘째 항목 열림 200ms를 같은 전환에서 처리 |
| 2100~3600ms | 둘째 내용 유지 |

컨테이너가 커지면서 아래 제목도 실제로 밀려야 한다. 텍스트는 스케일하지 않는다. 열림 이후 높이는 auto로 돌아가 내용 증가에 대응한다. 빠른 반복 입력에는 현재 높이에서 목표 높이로 전환하며, 이미 취소된 전환의 종료 이벤트가 새 상태를 덮어쓰지 못하게 한다. 폭·글꼴·내용이 바뀌면 높이를 다시 계산한다. 상세에서 단일/복수 모드, Enter·Space, 긴 본문과 즉시 열림 대안을 확인한다.

### C44 스켈레톤

장면은 32px 아바타 자리, 제목 1줄, 본문 2줄의 카드다. 최종 콘텐츠의 박스와 자리표시 박스를 일치시켜 로딩 종료 시 크기 변화가 없게 한다. 제목은 약 65%, 본문은 90%와 75% 길이를 시작안으로 둔다.

| 시간 | 상태·동작 |
| --- | --- |
| 0~600ms | 정적인 자리표시 |
| 600~1800ms | 잘린 가상 광택 레이어가 왼쪽 밖에서 오른쪽 밖으로 한 번 이동 |
| 1800~1960ms | 모의 데이터 완료. 자리표시는 제거하고 실제 카드 opacity를 160ms로 표시 |
| 1960~3200ms | 완성된 콘텐츠 유지 |

상세에서는 지연 400~3000ms, 성공·빈 결과·오류를 선택한다. 재시도와 초기화가 이전 실행의 늦은 완료를 막아야 한다. 모션 감소에서는 광택이 없는 정적 자리표시와 처리 중 문구를 사용한다. 예제 전체는 aria-busy를 적절히 변경하고 자리표시 한 줄씩을 반복 읽지 않는다. 완료 콘텐츠를 fade로 중복 렌더링할 때 같은 정보가 두 번 읽히지 않도록 한다.

### C13 콤보박스

장면은 도시 레이블, 텍스트 입력, 열기 버튼, 추천 목록, 활성 항목, 선택 결과다. 기본 유형은 편집 가능·수동 선택으로 둔다. 추천 데이터는 고정한 도시 목록을 쓰고 검색 결과를 실제로 필터한다.

| 시간 | 상태·동작 |
| --- | --- |
| 0~600ms | 빈 입력과 닫힌 목록 |
| 600~1100ms | 시연 모델에 `서`를 입력하고 추천 목록을 엶 |
| 1100~1220ms | 추천 목록 opacity·4px 이동으로 표시 |
| 1220~2000ms | 첫 후보에서 다음 후보로 활성 항목 변경 |
| 2000~2120ms | 선택 확정·목록 닫기 |
| 2120~3600ms | 확정한 입력값 표시 |

상세에서 실제 IME 입력 중에는 조합값을 임의 확정하거나 Enter를 항목 선택으로 가로채지 않는다. 방향키 이동·Enter 선택·Esc 닫기·마우스 선택·무결과·비활성 항목을 확인한다. label·expanded·controls·active descendant·selected 상태를 실제 목록과 일치시킨다. 선택 전용 변형은 별도 모드로 설명한다. 기능 기준은 [W3C Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/)를 따른다.

### C46 데이터 그리드

장면은 품목·수량·가격 3열과 4행, 열 헤더, 선택 셀, 편집 input, 상태 안내다. 목록 대표 상태는 수량 셀이 선택된 모습이다. 일반 표와 달리 복합 위젯의 키보드 이동을 보여주는 것이 목표다.

| 시간 | 상태·동작 |
| --- | --- |
| 0~600ms | 첫 데이터 셀 선택 |
| 600~1200ms | 오른쪽 셀로 선택 위치 변경, 셀 경계 표시 |
| 1200~1800ms | 편집 상태로 전환해 input 표시 |
| 1800~2400ms | 수량 값을 변경하고 확정 |
| 2400~2700ms | 변경한 셀의 배경 강조를 300ms로 제거 |
| 2700~3800ms | 새 값과 선택 위치 유지 |

탐색 상태에서는 roving tabindex 등 명시적인 초점 전략을 쓰고 방향키는 셀 이동을 담당한다. 편집 상태에서는 텍스트 커서 이동과 셀 이동을 충돌시키지 않는다. Enter/F2 진입, Enter 확정, Esc 취소, Tab과 행 경계 정책을 명시한다. 유효하지 않은 값은 오류를 보이고 기존 값을 보존한다. 모바일은 표 관계가 필요한 이 예제에서 가로 스크롤과 행 상세 대안을 비교한다. 단순히 카드 목록으로 바꿔 같은 체험이라고 설명하지 않는다. 기준은 [W3C Grid](https://www.w3.org/WAI/ARIA/apg/patterns/grid/)다.

## 개별 UI 제작 완료 판정

각 ID는 장면이 용어의 의미를 드러내는지, 시연 전후 관계가 설명과 맞는지, 직접 체험이 같은 규칙을 쓰는지 확인한다. 일반적인 2~4초 시연 시간에 맞추기 위해 오류 처리나 실제 체험 규칙을 축소하지 않는다. 파일 업로드·스켈레톤 등의 모의 처리 시간은 명확히 알린다.

이 문서는 이미지와 동작을 제작할 수 있는 설계 명세다. 60개의 시안·실행 데모·브라우저 테스트가 이미 만들어졌다는 의미는 아니다. 대표 6개의 정지 장면·타임라인 시안과 프로토타입으로 먼저 실제 품질을 확인한다.
