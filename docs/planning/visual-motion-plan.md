# UI 이미지와 애니메이션 구현 계획

작성일: 2026-11-26. 상태: 구현 전 상세 설계안. [전체 기획안](README.md)과 [디자인 적용안](design-reference.md)의 시각 예시·실제 체험 부분을 구체화한다. [60개 UI별 명세](ui-motion-specs.md)는 이 문서의 제작 규칙을 공유한다. 아래 수치와 구조는 프로젝트 제안이며 구현·시안 검증 결과가 아니다.

적용 정책 변경: 이후 사용자 수정 요청으로 현재 프로토타입은 목록·상세의 자동 반복을 사용한다. 목록의 재생·직접 체험 버튼과 상세의 재생·속도·단계·모션 감소 조작을 제거했다. 보이는 모든 카드를 재생하고 화면 밖·문서 숨김·상세 진입 중에는 목록을 정지한다. 아래의 최초 설계에서 한 번 재생·최대 2개·수동 제어에 관한 부분은 대체되었다. 현재 구현과 검증은 [프로토타입 검증 기록](../prototype-review.md)을 따른다.

## 이미지 제작 방식

용어별 대표 이미지는 HTML·CSS·SVG로 그린 실제 UI의 정적인 대표 상태로 만든다. 모달·입력·표·바텀시트를 각각 별도의 화면 구조로 제작한다. 목록의 이미지와 애니메이션, 상세의 조작 가능한 UI가 같은 동작 모델과 스타일 원본을 사용하도록 한다.

| 대상 | 제작 방식 | 사용 이유 |
| --- | --- | --- |
| 버튼·입력·카드·표·레이어 | 의미에 맞는 HTML과 CSS | 크기·문구·테마·상태를 수정하고 실제 조작을 연결하기 쉬움 |
| 체크·닫기·돋보기 등 아이콘 | 자체 SVG 또는 선정한 한 가지 SVG 아이콘 체계 | 선 굵기·크기 통일, 확대 시 선명도 유지 |
| 배경 콘텐츠 | 공통 가상 앱의 텍스트·행·카드 | UI가 나타나는 위치와 맥락을 설명 |
| 파일·아바타 자리 | SVG 또는 CSS 도형 | 실제 사용자 사진이나 외부 이미지 없이도 동작 설명 가능 |
| 정지 미리보기 | 같은 컴포넌트의 지정 상태 | 모션 끄기·첫 로딩·재생 오류에서도 동일 UI 표시 |
| PNG·WebP | 필요할 때 검증된 상태를 캡처해 생성하는 보조 산출물 | 공유·문서·화면 비교용. 실행 화면의 원본으로 사용하지 않음 |

기본 60개에 사진·AI 생성 이미지·GIF·MP4·Lottie를 필수 자산으로 두지 않는다. UI 구조와 글자가 정확하고 직접 조작 가능한 것이 목적이기 때문이다. 그림이 필요한 특정 원고가 추가되면 그 자산만 별도로 검토한다. 참고 사이트의 화면·로고·문구·애니메이션 파일은 그대로 가져오지 않고 지정된 시각 스타일에 맞춰 자체 제작한다.

UI의 의미를 만드는 형태는 유지한다. 예를 들어 모달에는 배경 차단, 바텀시트에는 하단 접점, 툴팁에는 대상 요소, 스켈레톤에는 최종 콘텐츠와 대응하는 자리표시가 반드시 있어야 한다. 단순히 흰 박스에 서로 다른 이름만 붙이지 않는다.

## 공통 시각 무대

목록용 무대의 논리 크기를 320×200, 비율을 8:5로 제안한다. 흰 배경, 얇은 회색 프레임, 둥근 모서리 안에 간단한 가상 앱을 배치한다. 카드가 작아지면 도식적인 미리보기만 비율에 맞춰 줄이고, 카드 밖 명칭·설명·재생 버튼은 실제 크기와 가독성을 유지한다.

미리보기 안의 장식용 줄은 텍스트 막대로 단순화할 수 있지만 해당 UI를 식별하는 버튼·선택 표시·도움말 대상·레이어 위치는 보존한다. 축소된 글자에 필수 사용 안내를 맡기지 않는다. 상세 체험에서는 본문·컨트롤을 읽고 누를 수 있는 실제 크기로 다시 배치한다.

| 공통 부품 | 구성 |
| --- | --- |
| 가상 앱 | 작은 제목, 중립적인 텍스트 2~3줄, 주 행동 또는 목록 |
| 입력 무대 | 레이블, 입력란, 도움말·오류 영역 |
| 탐색 무대 | 현재 위치, 3~5개 목적지, 전환될 본문 |
| 데이터 무대 | 식별 가능한 열·행, 선택·정렬 상태 |
| 레이어 무대 | 배경, 트리거, 오버레이 여부, 대화상자 또는 패널 |
| 모션 무대 | 시작·끝 위치, 같은 크기의 대상, 현재 모션 이름 |

단계 설명은 무대 아래에 짧게 표시한다. 예: `버튼 누름 → 알림 표시 → 자동 닫힘`. 이 문장은 정지 상태에서도 읽을 수 있어야 한다. 가상 포인터·터치 표시는 SVG 도형으로 만들고 목록의 자동 시연에만 사용한다. 사용자의 실제 커서처럼 동작하거나 실제 키보드 초점을 빼앗지 않는다.

## 세 가지 보기 모드

| 모드 | 목적 | 조작 방식 |
| --- | --- | --- |
| 대표 상태 | UI가 무엇인지 즉시 식별 | 대표 장면을 정적으로 렌더링 |
| 자동 시연 | 동작의 전후 관계 이해 | 미리 정한 2~4초 시나리오를 한 번 재생 |
| 직접 체험 | 실제 사용 규칙 확인 | 사용자가 마우스·키보드·터치로 조작 |

목록은 대표 상태와 자동 시연을 제공한다. 상세는 직접 체험을 기본으로 하고 예시 재생을 별도로 선택할 수 있다. 직접 체험 중 자동 시나리오가 개입하지 않는다. 모드 변경은 이전 동작을 정리하고 명시적인 초기 상태로 돌아간다.

목록용 자동 시연은 실제 focus·click을 강제로 발생시키지 않고 같은 UI 모델의 `open`, `select`, `setQuery` 같은 의미 있는 동작을 호출한다. 상세에서는 실제 DOM 이벤트가 그 동작에 연결된다. 네이티브 select·파일 선택기는 브라우저가 그리는 화면이므로 목록에서 가짜 시스템 창을 재현하지 않는다. 목록에는 제어 전후 상태, 상세에는 사용자가 실제로 여는 네이티브 컨트롤을 제공한다.

## 애니메이션과 상태 구현

| 용도 | 구현 제안 |
| --- | --- |
| 사용자 입력에 따른 단순 전환 | CSS transition과 상태 변경 |
| 스피너·반짝임 | CSS keyframes, 재생·정지 상태 연결 |
| 여러 단계의 목록 자동 시연 | 공통 시나리오 시계 + Web Animations API 또는 결정 가능한 상태 렌더링 |
| 스크롤·드래그·제스처 | 실제 스크롤·Pointer Events와 상태 처리, 필요한 프레임 갱신만 requestAnimationFrame |
| 아코디언·배너 공간 변화 | 콘텐츠 높이를 측정해 제한된 영역에서 전환 |
| 반응형 배치·그리드 편집 | 실제 CSS 재배치·선택·입력. 의미 없는 확대·회전을 추가하지 않음 |

[Web Animations API](https://developer.mozilla.org/en-US/docs/Web/API/Web_Animations_API)는 시간과 표시 변화를 연결하는 근거로 확인했다. 일시정지가 필요한 자동 시연에 CSS transition만 붙여 놓고 타이머를 멈추는 방식은 사용하지 않는다. 자동 시연의 논리 시계와 실제 애니메이션 시간을 함께 제어한다. 필수 라이브러리로 GSAP·Framer Motion 등을 먼저 도입하지 않고 필요한 동작과 브라우저 지원을 확인해 선택한다.

데이터 처리 시간과 움직임 시간은 별도 값이다. 예를 들어 `1200ms의 모의 로딩`과 `160ms의 콘텐츠 등장`을 구분한다. 설정한 시간은 예제를 위한 값이며 실제 서비스의 처리 시간으로 설명하지 않는다. 네트워크·현재 시간·무작위 값에 기대지 않고 고정된 시나리오 데이터로 재생한다.

### 공통 시간값 시작안

| 역할 | 제안값 |
| --- | --- |
| 선택·초점 보조 표시 | 100~150ms |
| 짧은 페이드·팝오버 | 120~180ms |
| 아코디언·탭 전환 | 180~220ms |
| 모달 진입 | 220ms |
| 드로어·바텀시트 진입 | 280~320ms |
| 퇴장 | 일반적으로 140~220ms, 개별 명세 우선 |
| 자동 시연 준비 장면 | 보통 500~600ms |
| 대표 결과 읽기 | 보통 800~1400ms |
| 전체 자동 시연 | 개별 명세의 2~4초 |

일반 진입은 `cubic-bezier(0.2, 0, 0, 1)`, 퇴장은 `cubic-bezier(0.4, 0, 1, 1)`을 시작안으로 둔다. 회전·진행 샘플은 linear, 이징 비교는 비교 대상 곡선을 사용한다. 모두 프로젝트 설계값으로 시안에서 조정한다. CSS 모션의 기반은 [MDN Transitions](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Transitions/Using), [Animations](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Animations/Using), [Easing](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Values/easing-function)에서 확인했다.

transform·opacity 전환을 우선 사용하되 레이아웃 변경이 UI의 핵심이면 실제 높이·배치를 전환한다. 아코디언 텍스트를 scaleY로 찌그러뜨리거나, 진행 막대를 늘리면서 퍼센트 글자까지 늘리지 않는다. `transition: all` 대신 변하는 속성을 명시한다.

## 목록 재생 제어

상태는 `ready / queued / playing / paused / finished / error`로 구분하고, 일시정지 이유를 `사용자 / 화면 밖 / 문서 숨김 / 상세 열림 / 전체 모션 끄기`로 별도 기록한다. UI 자체의 열림·선택·로딩 상태와 플레이어 상태를 섞지 않는다.

1. 최초에는 지정된 대표 상태를 즉시 표시한다. JavaScript가 준비되지 않았거나 데모 로딩이 실패해도 빈 박스가 되지 않도록 정적 마크업·상태 설명을 남긴다.
2. 처음 카드의 60% 이상이 보이면 자동 재생 후보로 등록한다. 한 번에 최대 2개, 위쪽에 가까운 카드부터 재생한다. 이 임계값은 제품 제안이다.
3. 사용자가 재생을 누른 카드는 대기 중인 자동 시연보다 우선한다. 전체 활성 수 2개를 유지하려면 자동 시연 하나를 일시정지한다.
4. 카드가 화면에서 벗어나거나 브라우저 탭이 숨겨지면 표시 애니메이션·시나리오 시계·반복 효과를 함께 일시정지한다. 재진입 후 자동으로 이어서 재생하는 것은 자동 정지 이유만 제거됐을 때다. 사용자 정지는 재생 버튼으로만 해제한다.
5. 한 번 끝난 카드는 같은 목록 상태에서 자동 반복하지 않는다. 검색으로 목록이 다시 만들어져도 `demo ID + 버전` 단위의 세션 재생 기록을 유지한다. 다시 보기는 명시적 선택으로 제공한다.
6. 마지막 프레임을 유지한다. 토스트처럼 사라지는 것이 핵심이면 사라진 결과와 배경의 저장 완료 상태를 유지하고 단계 설명을 남긴다. 대표 상태 보기는 별도 동작으로 돌아갈 수 있다.
7. 상세가 열리면 목록 시연을 정지한다. 상세를 닫아도 사용자가 정지한 항목을 임의로 다시 시작하지 않는다.

화면 노출은 [Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API), 탭 숨김은 [Page Visibility API](https://developer.mozilla.org/en-US/docs/Web/API/Page_Visibility_API)를 사용한다. 화면 교차 여부가 다른 요소에 가려지지 않았음을 완전히 보장하는 것은 아니므로 상세 열림 등 서비스 상태도 함께 반영한다.

시계는 실행 중인 경과 시간만 누적한다. 탭이 오래 숨겨졌다 돌아와도 시나리오가 한 번에 끝나지 않아야 한다. 필요한 [requestAnimationFrame](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame)은 경과 시간으로 계산하고 프레임 수로 시간을 계산하지 않는다. 각 카드에 끝없는 프레임 루프를 만들지 않는다.

## 직접 체험과 격리

상세에서는 PC·모바일 폭, 기본·오류·비활성 등 해당 UI에 필요한 상태, 움직임 설정, 초기화를 제공한다. 슬라이드 거리를 조절하는 모션 학습 UI와 실제 폼의 입력값을 바꾸는 UI는 컨트롤 구성을 구분한다. 모든 UI에 동일한 옵션을 억지로 넣지 않는다.

자동 시연에는 재생·일시정지·처음부터·대표 상태 보기를 제공한다. 상세의 시연 확인에는 0.5배·1배 속도와 단계 이동을 시작안으로 두되 직접 체험의 실제 입력 속도까지 변경하지 않는다. 속도 조절 시 준비·대기·전환 시간은 같은 논리 시계로 변하고, 가독성을 위해 고정할 안내 시간은 명시적으로 분리한다. 모션 감소 중에는 단계 이동을 기본으로 사용한다. 특정 시간으로 이동하는 기능은 결정 가능한 자동 시나리오에만 적용하며 실제 파일 선택이나 외부 요청 이력을 되감는 기능으로 만들지 않는다.

목록 미리보기는 경량의 컴포넌트 렌더러를 쓴다. 미리보기 안에서 페이지 단위 스크롤·포커스·top layer를 사용하지 않고 지정된 무대 안의 상태로 표현한다. 개별 CSS는 범위를 제한하며 포털을 사이트 body에 만들지 않는다. 미리보기의 모달 배경 차단은 축소된 설명 표현이다.

상세의 실제 데모는 필요한 시점에 별도 문서 iframe으로 로드한다. 진짜 dialog·popover·스크롤·포커스는 그 문서 안에서 실행한다. iframe은 예를 들어 PC 720px·모바일 360px의 내부 레이아웃을 선택할 수 있지만, 실제 터치·OS 동작 검증을 대신하지 않는다. 바깥 공간보다 큰 PC 폭은 프레임 영역 안에서 스크롤·축소 보기로만 비교하고 체험 시에는 읽을 수 있는 배율을 제공한다.

iframe의 지원 조건은 [MDN iframe](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/iframe)을 참고한다. sandbox는 기본적으로 스크립트 실행만 허용하는 방향으로 검토하고 필요한 권한을 예제별로 최소 추가한다. 같은 출처의 쓰기 API·관리자 상태 접근을 허용하지 않는다. opaque origin을 쓰는 경우 메시지를 origin 문자열만으로 신뢰하지 않고 frame source·세션 nonce·허용 명령·payload 스키마를 검증한다. 실제 DOM 보안 구성을 구현 단계에서 별도 확인한다.

폼 제출·링크·파일 업로드는 데모 안의 모의 동작만 수행한다. 서버 변경·실제 결제·실제 메시지 발송 등은 만들지 않는다. 파일 예제는 기본적으로 제공된 샘플 파일로 흐름을 확인하며, 로컬 파일 선택은 명시적인 사용자 조작일 때만 읽고 외부 전송하지 않는다.

## 코드 원본과 관리 항목

데모 하나는 `ID·버전 / 장면 구조 / 상태와 동작 / 자동 시나리오 / 대표 상태 / 두 실행 형식 / 설정 스키마 / 모션 감소 대안 / 검증 기준`을 갖는다. 코드의 역할을 다음처럼 나눈다.

| 구성 | 책임 |
| --- | --- |
| 장면·데이터 | 레이어, 고정 예시 문구, 행·옵션·선택 값 |
| 동작 모델 | 열기·닫기·입력·선택·처리 상태 전환 |
| 직접 실행 파일 | HTML·CSS·JS 또는 React·TS에서 실제 사용자 이벤트 연결 |
| 자동 시나리오 | 시점별 의미 동작, 장식용 포인터, 데모용 모의 대기 |
| 대표 상태 | 정지 상태에서 의미가 잘 드러나는 키프레임 |
| 표시 코드 | 선택한 실행 형식의 실제 소스와 설정. 자동 포인터·목록 재생기는 기본 복사 코드에서 제외 |
| 검증 | 두 실행 형식의 동작 일치, 목록·상세 형태 일치, 모션 감소·재생 제어 |

HTML·JS와 React·TS를 기계적으로 완전 자동 변환한다고 가정하지 않는다. 같은 동작 명세와 디자인 토큰을 쓰는 두 구현을 만들고 각각 실행한다. 사용자에게 보이는 형식의 데모와 복사 코드가 같아야 한다. 목록은 기본 React 렌더러를 사용하되, 상세에서 바닐라 형식을 선택하면 바닐라 실행 파일을 직접 체험한다.

관리자는 문구·옵션·대표 상태·허용된 시간·사용할 시나리오·지원 환경을 설정한다. 색상·간격은 공통 토큰을 기본으로 하고 개별 용어에 필요한 값만 예외로 둔다. 모션 학습 UI 외에는 일반 콘텐츠 관리자에게 무제한 키프레임 편집을 제공하지 않는다. 새 동작은 개발자가 코드와 명세를 등록한다는 기존 선택을 따른다.

예제 버전 변경 시 기존 게시 리비전은 기존 버전을 참조한다. 관리자에서 새 버전과 이전 버전의 대표 상태·자동 시연·직접 체험을 비교한 뒤 게시한다. DB 문구만 바꿔 코드 예제와 어긋나면 게시 검증에서 알려준다.

초기화는 진행 애니메이션·모의 요청·타이머·프레임·포인터 캡처·선택 상태를 정리하고 기본 데이터로 되돌린다. 비동기 응답에는 실행 세대 ID를 둬 초기화 후 이전 실행의 늦은 결과가 덮어쓰지 못하게 한다. 데모 닫기·형식 변경·폭 변경·리비전 변경 시에도 동일한 정리 규칙을 사용한다.

## 모션 감소와 접근성

모션 감소 프로필은 [UI별 명세](ui-motion-specs.md)에 연결한다.

| 프로필 | 적용 |
| --- | --- |
| R0 즉시 상태 | 색·선택·내용을 즉시 변경. 보간 이동·확대 제거 |
| R1 전후 비교 | 열기 전·후를 정적 장면 또는 단계 버튼으로 확인. 슬라이드·스케일 제거 |
| R2 처리 상태 | 회전·반짝임을 제거하고 처리 중·완료 문구와 정적 표시로 상태 설명 |
| R3 조작 대안 | 스크롤·드래그·스와이프 자동 시연을 중단하고 버튼·수치 입력·직접 선택 제공 |
| R4 모션 학습 | 기본은 시작·중간·끝의 정지 프레임 비교. 명시적 재생에도 항상 정지 기능 제공 |

운영체제의 prefers-reduced-motion 또는 사이트의 전체 모션 끄기가 켜져 있으면 목록 자동 재생을 하지 않는다. 사용자에게 상황을 알리고 정지된 상태·단계 설명을 보여준다. 상세의 명시적 모션 비교 재생은 설정을 무시해 정상 속도로 갑자기 움직이지 않으며, 사용자가 별도로 실제 모션 확인을 선택한 경우에만 재생한다. 해당 설정의 기술 근거는 [MDN prefers reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)이다.

목록 무대 내부는 장식으로 처리하고, 실제 재생·정지 버튼과 UI 설명은 접근 가능한 이름을 제공한다. 축소 화면의 가짜 버튼은 탭 순서나 live region에 포함하지 않는다. 상세의 실제 컨트롤만 의미와 키보드를 갖춘다. 로딩 안내는 화면 읽기 프로그램에 매 프레임 반복 전달하지 않는다. 상태는 적절한 시점에 한 번 전달한다.

## 제작 검토와 단계 경계

60개 모두에 장면 구성·자동 시나리오·속성과 시간·직접 조작·모션 감소 프로필을 정의한다. 복잡한 6개는 밀리초 단위 단계와 상태 전이를 더 자세히 기록한다. 6개만 제작하고 전체 완료로 간주하지 않는다.

구현에 앞서 대표 정지 장면과 전환 전후 장면을 화면 시안에서 확인한다. 시안을 그리기 전 기획 문서만으로 색·간격·겹침·리듬의 실제 품질을 확정할 수는 없다. 다음 단계의 순서는 `대표 상태·스토리보드 시안 → 6개 동작 프로토타입 → 재생·직접 체험 검증 → 최종 40~60개 확장`이다. 이는 앱 전체 개발 전에 시각·동작을 확인하기 위한 중간 검증이다.

구현 후에는 한 시나리오를 10번 다시 재생했을 때 결과가 같은지, 일시정지 중 타이머·반짝임까지 멈추는지, 탭 숨김 후 복귀에서 시간이 건너뛰지 않는지, 초기화 후 이전 응답이 도착하지 않는지 확인한다. 목록에서 상세로 갔다 돌아올 때 포커스와 목록 위치를 확인한다. 수치 기준과 수동 점검은 [검토 계획](qa-plan.md)에 합친다.
