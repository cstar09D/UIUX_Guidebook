# UI Notes 프로토타입 검증 기록

최신 결과는 [모달 체험·대안 카드·날짜 형태 분리](modal-date-split-review.md)를 참고하세요. 현재 목록은 39개이며 아래 내용은 최초 6개 프로토타입과 관리자 단계의 이력입니다. [3단계 확장 기록](patterns-review.md)과 [앞선 사용성 개선](usability-refinements.md)도 별도로 보관합니다.

확인일: 2026-11-26. 대표 6개 UI의 형태·움직임·직접 조작을 확인하기 위한 로컬 프로토타입이다. 전체 출시 범위 40~60개를 완료한 결과는 아니다.

## 자동 검사

- TypeScript 타입 검사 통과.
- 자동 테스트 9개 통과: 보이는 모든 카드의 자동 재생, 다중 주기 반복, UI별 재생 길이, 화면 밖·문서 숨김·상세 진입 정지와 복귀, 같은 데모를 연결한 콘텐츠의 독립 반복, 명칭 검색, 동작·생김새 검색, 모호한 검색과 무결과, SQLite 영구 저장·숨김·휴지통·복원·순서 트랜잭션·리비전 충돌·재연결.
- Next.js 프로덕션 빌드 통과. 빌드 결과의 경로는 `/`, `/admin`, `/api/terms`다.
- 개발 서버 종료 후 프로덕션 서버로 재시작하고 세 경로의 HTTP 200 응답, 콘텐츠 6개·노출 상태·원래 순서의 보존을 확인했다.
- 저장소 테스트는 별도 임시 DB에서 수행했다. 사용자 작업 DB의 데이터를 테스트 초기화로 덮어쓰지 않았다.

## 검증 한계

### 상세 콘텐츠 보강 검증

- ‘동작 메모’ 영역과 관련 표시 데이터를 제거했다.
- 대표 6개 전체의 사용 가이드를 정의·사용 상황·흐름·주의점·화면별 대안·체험 방법으로 보강했다. 21개 상황별 화면 예시의 선택과 조건/처리 설명 전환을 브라우저에서 확인했다.
- 6개 × 4개 직무 안내를 목표·구체적 작업 3개·협업 전달 예시·검토 질문으로 제공한다. 24개 안내의 전환과 내용 표시를 확인했다.
- 코드는 ‘UI 부분 코드’가 기본이며 React 컴포넌트/CSS, HTML/CSS/JavaScript를 개별 선택한다. ‘전체 실행 예제’를 선택한 경우에만 독립 HTML 또는 해당 UI 하나의 App.tsx를 표시한다. 6개 UI 모두 두 형식의 부분/전체 전환을 확인했다.
- 6개 UI의 코드 표시 영역은 390px·320px에서 가로 넘침이 없었다. React 부분 코드와 전체 예제 12개는 원래 데모 모듈에 의존하지 않고 별도 타입 검사를 통과했다.
- 21개 설명용 화면 예시는 320px에서 모두 가로 넘침 없이 표시됐다. 분리한 스타일을 사용하는 HTML 데모 6개의 핵심 조작을 다시 확인했고, 스켈레톤의 빈 결과 → 첫 기록 추가와 데이터 그리드의 오류 → 수정 확정을 확인했다.
- ‘현재 코드 파일 저장’으로 받은 ui.html에 문서 전체가 아닌 선택한 HTML 조각만 들어 있는 것을 확인했다.
- 부분 코드의 문서 틀 제외, 다른 UI 구현 제외, JavaScript 구문·CSS 파싱을 포함해 자동 검사 11개와 최종 프로덕션 빌드를 통과했다.

다음 한계는 위 검증에도 동일하게 적용한다.

브라우저의 복사 실행은 성공 응답을 받았지만, 검증 도구의 가상 클립보드는 내용 읽기·붙여넣기에서 빈 상태를 반환했다. OS 클립보드의 실제 내용까지 검증한 것으로 기록하지 않는다. 코드는 직접 선택하거나 예제 파일로 저장하는 경로도 제공한다.

모바일 확인은 데스크톱 브라우저의 뷰포트 변경이다. iOS·Android 실기기, 실제 IME 조합 과정, 화면 읽기 프로그램, 복수 브라우저의 전체 접근성 검증은 아직 수행하지 않았다. 시트의 실제 터치 드래그 임계값과 가상키보드 동작도 후속 실기기 점검 대상이다.

운영용 인증·게시/초안·전체 변경 이력·카테고리 자체 관리·JSON 가져오기·전체 DB 백업 복구는 아직 구현하지 않았다. 관리자 변경은 SQLite에 직접 반영되는 로컬 단일 운영자 프로토타입이다.

실행과 폴더 구조는 [프로젝트 실행 안내](../README.md), 요구사항과 후속 범위는 [기획안](planning/README.md)을 따른다.

## 콘텐츠 관리자 확장 검증

기존 ‘검증 한계’ 중 게시 이력·카테고리 자체 관리·가져오기·콘텐츠 전체 백업은 이번 단계에서 구현했다. 운영용 로그인과 외부 공개, 실기기 접근성 검증은 후속 범위다.

- 현재 편집본과 게시본을 분리하고, 기존 SQLite 레코드 6개의 명칭·발음·요약·카테고리·별칭·검색어·숨김·순서·버전을 이전 전 기록과 대조해 보존을 확인했다. 이전 전 복구 파일을 자동 생성했다.
- 별도 임시 DB와 3001번 검증 서버에서 사용 가이드·화면 예시·직무별 안내를 수정해 저장했다. 사이트에는 기존 게시본이 남고, 저장된 초안 미리보기에는 수정 내용이 표시됐다. 게시 후 세 영역이 함께 갱신됐다.
- 이전 버전 복원이 새 초안을 만들고 현재 게시본은 유지하는 것을 확인했다. 미완성 초안은 저장되고 게시 시 누락 항목을 안내했다.
- 새 용어 작성·기본 가이드 불러오기·게시·숨김/노출·휴지통 이동/복원·순서 변경을 확인했다. 테스트용 콘텐츠는 사용자 DB에 추가하지 않았다.
- 카테고리 추가·연결 콘텐츠 이동 후 삭제, 태그 추가·연결·이름 변경의 반영과 사이트 태그 검색 결과를 확인했다.
- 전체 백업 다운로드 파일의 version 2, 초안/게시본과 이력 포함을 확인했다. 같은 파일을 실제 파일 선택 UI로 가져와 변경 대상 검토 → 확인 → 병합 적용까지 수행했고 자동 복구 지점 생성을 확인했다. 전체 교체·잘못된 파일·오래된 검토 토큰은 저장소 자동 검사에서 검증했다.
- 390px·320px의 5개 편집 탭에서 가로 넘침이 없고, 본문 하단에서도 닫기와 하단 행동이 화면 안에 유지됐다. PC의 관리 목록·편집기·백업 화면을 시각적으로 확인했다.
- 시뮬레이션 등록부 6개와 연결 수를 확인했다. 등록 연결과 시연 메타데이터 검사를 빌드에 추가했다.
- 최종 프로덕션 빌드와 자동 검사 20개가 통과했다. 관리자·초안 미리보기·API에서 로컬 주소 검사를 적용했고 실제 HTTP 요청으로 외부 Host와 Origin이 거부되는 것을 확인했다.

백업은 콘텐츠 JSON이며 앱·시뮬레이션 실행 소스는 프로젝트 폴더로 함께 보관해야 한다. 현재 가져오기 한도는 25MB다. 실제 OS 클립보드·실기기·화면 읽기 프로그램에 대한 기존 검증 한계는 유지한다.
