# Select 외형 통일 검수

확인일: 2026-11-26. 사용자 요청에 따라 상세의 운영체제 기본 선택창을 목록 미리보기와 같은 흰색·둥근 옵션 패널로 변경했습니다. React·HTML 체험, 목록·자동 관찰, 부분 코드·전체 예제를 같은 필드와 패널 스타일로 연결했습니다.

선택 전용 combobox/listbox의 키보드 의미는 [W3C APG Select-Only Combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/)를 확인했습니다. 사용자가 글을 입력해 검색하는 Combobox 항목과 구분해 설명합니다.

## 동작

- 필드 클릭·Enter·Space로 열기, 방향키·Home/End로 후보 탐색, Enter·Space·항목 클릭으로 선택합니다. 탐색 중에는 저장할 선택값을 바꾸지 않습니다.
- Esc·바깥 클릭·필드 재클릭은 임시 탐색을 취소합니다. Tab은 활성 후보를 선택한 뒤 다음 입력으로 이동합니다. DOM 초점은 필드에 두고 활성 후보를 aria-activedescendant로 연결합니다.
- 선택값과 적용값을 분리하고 다른 값을 선택한 경우 현재 적용값을 안내합니다. 미선택 오류·오류 초점·초기화·hidden input의 값도 연결했습니다.
- 화면 아래 공간이 부족하면 패널을 위로 열고 필요한 경우 내부 스크롤을 사용합니다. 현재 선택값에는 체크 표시, 활성 후보에는 파란 배경을 표시합니다.

## 확인 결과

- React·HTML 각각 미선택 오류 → 목록 탐색 → Esc 취소 → 매월 선택·적용 → End·Tab으로 분기별 선택 → 적용 전 기존값 안내 → 취소·바깥 클릭·초기화를 브라우저에서 확인했습니다.
- 390px·320px의 두 코드 형식에서 세 옵션과 선택 동작을 확인했습니다. 패널 경계가 iframe 안에 들어오고 가로 넘침이 없었습니다. [측정값](qa/select/select-mobile-metrics.json).
- [PC](qa/select/select-desktop.png)와 [모바일](qa/select/select-mobile.png) 화면을 시각적으로 확인했습니다. 목록과 상세에서 필드 테두리·모서리·옵션 패널·강조 스타일을 공유합니다.
- 프로덕션 빌드와 자동 테스트 34개가 통과했습니다. 신규 2개 검사는 선택과 적용·취소, 필수 오류, Tab 확정, 문자 탐색, 조합 Enter를 다룹니다. 모든 독립 코드 예제의 타입·구문 검사도 통과했습니다.
- HTML 파일 포맷팅으로 옵션 이름 주변에 생기는 공백을 제거해 결과 안내와 문자 탐색의 기준을 일치시켰습니다.
- 실제 Select 콘텐츠의 기본 안내 중 구현과 달라진 11개 필드와 출처를 갱신해 v2로 게시했습니다. 다른 25개 콘텐츠·게시본·메타 정보와 기존 이력 29건·설정은 SQL 원문 비교로 보존을 확인했습니다. Select의 기존 버전은 관리자 이력에 남습니다.

브라우저 자동화가 `분` 키 입력을 지원하지 않아 실제 한글 키보드의 문자 탐색은 검증하지 못했습니다. 문자 탐색은 React 이벤트 회귀 검사에서 확인했고, 여러 OS의 실제 IME·터치·화면 읽기 검수는 후속 범위입니다. 네이티브 선택창을 사용한다는 기존 검수 기록은 이 변경 이전의 이력입니다.
